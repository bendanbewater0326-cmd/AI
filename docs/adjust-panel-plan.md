# 左栏「调节」面板方案

> 状态：**待确认**（2026-10-23 摸底完成，等用户拍板后开工）
> 前置：特效面板已收官（「选风格」），本面板补「调数值」，两者共用同一份 `clip.effects`
> 目标：**零功能回归**——只加 UI 与入口，底层渲染 / 特效逻辑 / 导出完全不动

---

## 1. 摸底结论（决定方案边界的事实）

### 1.1 四类效果**全部已实现**，缺的只是左栏入口

| 效果 | 数据（`clip.effects` 里的 `type`） | 参数 | 读取函数 | 写入操作 |
|---|---|---|---|---|
| **调色** | `colorGrade` | `brightness` / `contrast` / `saturation` / `temperature`，各 `-100..100` | `currentGrade()`（`core/effectTarget.ts`） | `setClipEffect` |
| **曲线** | `curve` | `x1,y1,x2,y2`（`0..1`）；**UI 只暴露 y1(暗部)/y2(亮部)** | `curveOf()`（`render/curve.ts`） | `setClipEffect` |
| **LUT** | `lut` | `cube`（.cube 原文）+ `strength`（`0..1`） | `lutOf()`（`render/lut.ts`） | `setClipEffect` |
| **蒙版** | `mask` | `shape`(rect/ellipse) + `x,y,w,h`(`0..1`) + `invert`(1/0) | `maskOf()`（`render/mask.ts`） | `setClipEffect` |

**结论：不需要写任何渲染或数据结构代码。**

### 1.2 写入入口已统一

`setClipEffect` 是**同类型替换**（先删旧再写新），一次 dispatch = 一个撤销步。
属性栏已有的 4 个 commit 函数（`commitGrade` / `commitCurve` / `commitLutStrength` / `commitMask`）
就是标准写法，可以直接抽出来复用。

### 1.3 UI 现状：**只有滑块，没有数值输入**

现有控件是 `range` + 只读的 `<span>` 显示值：

```
[亮度 ──────●────── ] -20
```

**用户要求的"数值输入 + 滑块双操作"是新增能力**，需要新建一个组合控件。

### 1.4 没有折叠组件

左栏四个面板（素材/文本/转场/特效）都是**平铺**的，没有任何 `details` / `Collapse`。
分组折叠是新增能力。

### 1.5 属性栏 1357 行，四组效果 UI 内联其中

| 组 | 行号范围 | 约行数 |
|---|---|---|
| 调色 | 968–998 | 30 |
| 曲线 | 999–1042 | 44 |
| 蒙版 | 1043–1120 | 78 |
| LUT | 1121–1160 | 40 |

加上状态与 commit 函数（约 200 行），**这四组的实现散落在 250+ 行里**。

## 2. 定位分工（用户已明确）

| 面板 | 职责 | 交互单位 |
|---|---|---|
| **特效**（已完成） | 选风格：14 个预设一键套用 | 卡片（缩略图） |
| **调节**（本方案） | 调数值：滑块/数值精细调整 | 参数行 |

**共用同一份数据**：两者都读写 `clip.effects`，不存在第二份状态。
在调节面板改一个滑块 → 特效面板的"已应用"高亮会消失（因为 grade 不再等于任何预设）；
在特效面板点一张卡 → 调节面板的 4 个滑块立刻跟着变。

## 3. 面板结构

顺序与默认态按用户要求：**基础调色（默认展开）→ 曲线 → LUT → 蒙版（默认折叠）**。

```
┌─ 调节 ────────────────────────────┐
│                                     │
│  ▼ 基础调色                    重置 │   ← 默认展开
│    亮度   [────●────] [  -20 ]      │
│    对比   [──────●──] [   12 ]      │
│    饱和   [────●────] [    0 ]      │
│    色温   [──●──────] [  -35 ]      │
│                                     │
│  ▶ 曲线                        重置 │   ← 默认折叠
│  ▶ LUT                         重置 │
│  ▶ 蒙版                        重置 │
│                                     │
│  ⓘ 未选中片段时，调节应用在播放头所在片段 │
└─────────────────────────────────────┘
```

### 3.1 目标片段（关键设计）

调节面板**不要求先选中片段**——很多用户会直接拖滑块。
规则复用 `resolveEffectTarget(clip, selectedClipId, playheadFrame)`：
1. 有选中片段 → 用它
2. 否则用播放头所在片段
3. 都没有 → 面板禁用 + 一句提示（不给"看起来能点但没用"的状态）

### 3.2 每组的行为

| 组 | 控件 | 特殊处理 |
|---|---|---|
| **基础调色** | 4 行：滑块 + 数值输入（`-100..100`，步进 1） | 全部归零时**自动删掉 colorGrade effect**（避免留一个全中性效果） |
| **曲线** | 2 行：暗部 `y1` / 亮部 `y2`（`0..1`，显示 `0..100`） | 保持现状（只暴露 2 个可见点，`x1/x2` 内部固定）— 见待确认 ③ |
| **LUT** | 「载入 .cube」按钮 + 文件名 + 1 行强度（`0..100%`） | 文件选择复用现有实现；未载入时只有按钮 |
| **蒙版** | 形状下拉（矩形/椭圆）+ 4 行（x/y/w/h，`0..100%`）+ 反转开关 | 无蒙版时显示「＋ 添加蒙版」；有蒙版时显示全部 + 删除 |

每组标题右侧一个「重置」：把该组恢复中性（一次 dispatch = 一个撤销步）。

## 4. 共享控件（新增）

### 4.1 `AdjustRow`：滑块 + 数值双操作

```
亮度       [────●──────]  [ -20 ]  ◆
           ↑ 拖动实时预览   ↑ 输入框可编辑   ↑ 关键帧（仅蒙版/调色需要时）
```

**交互规则**（必须明确，否则两端行为不一致）：
- 拖滑块 → `onChange` 实时改 state（预览跟手）→ `onPointerUp` 才 dispatch（**一个撤销步**）
- 数值框 → `Enter` / `blur` 才 dispatch（避免输入过程每键一步）；`Esc` 撤销输入
- 数值框与滑块**互相同步**（同一 state）
- 超出范围 clamp 到 `min/max`（不报错）

### 4.2 `CollapsibleSection`：分组折叠

用原生 `<details>` + `<summary>`（零 JS），或自建 state。
**要点**：折叠态存 `localStorage`（`veditor:adjust:openGroups`），刷新后保持。

## 5. 双向同步机制

**这个项目已经踩过"同一份数据被两个组件各读一次 = 一定不同步"的坑**（MEMORY 记过：
属性栏与文本面板的预设列表各自 `useEffect(..., [])` 只读一次）。

本方案的对策：

| 做法 | 说明 |
|---|---|
| **都订阅 doc** | `useDoc((d) => d)`，每次 doc 变化重算，不做"只读一次" |
| **不各自持有副本** | 组件内只存"输入中的临时值"（`draft`），提交后立刻回到 doc 派生 |
| **单一写入函数** | 抽 `applyGrade/applyCurve/applyLut/applyMask` 到 `core/adjust.ts`，两个面板都调它 |

**验证方式**：E2E 里在左栏拖滑块 → 断言右栏对应滑块的值同步变化（反向也测一次）。

## 8. 待确认（5 项，需要你拍板）

### ① 属性栏要不要同步改造？

| 选项 | 好处 | 代价 |
|---|---|---|
| **A. 同步抽取**（推荐） | 单一实现，改一处两端生效 | 动 1357 行文件，有回归风险（靠保留 data-v + E2E 兜底） |
| **B. 先只做左栏** | 零风险 | 两套 UI 实现，以后改样式要改两处（技术债） |

**我倾向 A，但可以拆成两步**：S1–S4 先做左栏，S5 再统一。

### ② 曲线暴露几个控制点？

现状属性栏只给 **2 个**（暗部 y1 / 亮部 y2），`x1/x2` 固定在 1/3、2/3。
- **A. 保持 2 个**（最小改动，复刻现状）
- **B. 暴露 4 个**（x1/y1/x2/y2，能做 S 形曲线，但要考虑 x1<x2 的约束与 UI 表达）

### ③ 蒙版的关键帧按钮是否在调节面板也放？

属性栏蒙版组有关键帧按钮（◆，按播放头打点）。左栏要不要也放？
- **A. 放**（功能一致，但左栏空间紧）
- **B. 不放**（左栏只管静态值，关键帧仍去属性栏）

### ④ LUT 的「载入 .cube」放左栏吗？

LUT 需要文件选择器。左栏放了会和素材导入的拖拽区语义接近（容易误解）。
- **A. 放**（功能完整）
- **B. 只显示"已载入/未载入" + 强度，载入仍去属性栏**

### ⑤ 是否需要"重置全部"？

每组有"重置"，那要不要面板顶部再加一个「全部重置」（一次撤掉 4 类效果）？
- **A. 加**（快捷）
- **B. 不加**（避免误触把调色/曲线/蒙版全清掉）

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 动属性栏导致回归 | 保留全部 `data-v`；E2E 覆盖；S5 单独一步可回滚 |
| 两处读同一份数据不同步 | 都 `useDoc` 订阅 + 单一写入函数（`core/adjust.ts`） |
| 滑块拖动产生几十个撤销步 | 拖动只改 state，`onPointerUp` 才 dispatch |
| 左栏宽度不够（25%×1440−44 ≈ 296px） | 一行 = 标签(48) + 滑块(140) + 数值(52) + 关键帧(24) ≈ 264px，够用 |
| 蒙版 4 参数挤在一起 | 两列网格（x/w 一行、y/h 一行） |
