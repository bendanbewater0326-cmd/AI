## 3. 断点清单（按阻断程度排序）

### 3.1 阻断「产品成立」的三件事

1. **导出完全不存在（M3）**
   `package.json` 只有 react；`src/` 无 `VideoEncoder` 调用、无 muxer；顶栏「导出」是 `disabled` 占位。
   → 现在剪完的成片**带不走**。
2. **没有声音（R-006 / R-024 / R-032 无法验收）**
   `audioEngine.ts` 只做了重采样（带限 sinc）与采样数守恒，`App.tsx` 里没有 `AudioContext`。
   → 播放只有画面；音画同步这条生死线没被测过。
3. **AI 层 0%（M4）**
   没有 `Ctrl+K` 命令栏、没有语气判定、没有建议虚线、没有执行模式、没有 toast。
   `host.ts` 里 `AIModelPort` 接口定义了但所有 adapter 都 `return null`。

### 3.3 实测到的实现缺陷（有像素证据）

1. **空态提示 x/y 传反**：`timelinePainter.ts` 里
   `fillText('把素材拖到时间线上', RULER_HEIGHT + TRACK_HEIGHT * 1.5, width / 2 + 28)`
   —— 第二个参数是 x，第三个是 y。文字被画到画布外（y≈628，画布高 192）。
   证据：空态画布全图仅 **259 个深色像素**（= 刻度 + 三个轨道名），无该文字。
2. **片段块压住轨道头**：块从 `x=0` 起画，覆盖 56px 轨道头。截图里 V1 的名字被块遮住，看起来像"片段落在 A1 上"。
3. **预览首帧不渲染**：`App` 只在 `transport.onFrame` 里调 `renderPreviewFrame`。导入后停在黑屏，动一下播放头才出画。
4. 轨道顺序与 PRD 相反（见上表）。

## 关于「workbuddy 侧能否调用模型」（Q3 结论）

**能，且不需要用户自己的 API Key。** 路径是 WorkBuddy 云服务的 LLM 模块：

- SDK：`@tencent-ai/workbuddy-cloud-sdk`（`createWorkBuddyCloud({ endpoint, publishableKey })`）

3. 做成 skill 时，把「prompt 组装 + ClipOperation schema 校验」放进 skill，模型通道交给宿主或云 LLM。

| 文件 | 职责 |

## B3 剪区间的语义（踩坑记录）

第一版 `removeRange` 用"切分 + 删除"，剪头后片段从第 30 帧开始——**原地留了个 30 帧的黑洞**。
用户说"剪掉开头 3 秒"想要的是"后面的接上来"。改为片内 ripple：
- 剪头 → 只改素材入点（`startFrame` 不动）
- 剪尾 → 只改素材出点
- 剪中间 → 切两刀 + 删中间 + 后半段左移

顺带解决两个连带 bug：① 剪头后原 `clipId` 消失，导致连续两条指令引用同一片段时第二条失败；
② 重叠判定用了"删除前"的轨道快照，中间段还在，永远判重叠。

# 批次 C1 交付记录（功能齐全 · 第一批）

## C1-1 文字（R-034）

**数据模型**：文字挂在 `Clip.text` 上，不建"文字素材"。
好处是复制/裁剪/移动/撤销全部复用片段那套逻辑，也不会被"刷新后素材句柄失效"波及。
`assetId` 为空串、不参与素材帧映射，`playbackEngine` 在层解析阶段就分流。

**渲染**：`render/textLayer.ts` 把文字画成**项目分辨率的透明底 canvas**，带缓存（尺寸+内容为 key）。
为什么不用"紧贴文字的小图"：合成器的 `fitSize` 会按 contain 缩放进画面，小图会被放大到铺满，字号立刻失真。

**入口**：时间线工具条「＋ 文本」→ 播放头处 3 秒文本片段，落在最上层视频轨（否则会被素材盖住）。
**属性**：内容（多行）/ 字号 / 颜色 / 对齐，改完立刻重绘（缓存 key 变化）。

## C1-2 调色（R-035）

- 参数放 `clip.effects` 里的 `colorGrade`（`brightness/contrast/saturation/temperature`，±100），
  不是塞进 `transform`——`Effect` 天生带 `keyframes`，C3 加关键帧时不用再改数据模型。
- 着色器里做（`applyGrade`），**预览与导出共用同一条 GPU 路径**；CPU 逐像素会因为舍入与 GPU 不一致。
- 中性值 `(0,1,1,0)` 与"不加调色"完全等价，老工程不会因为这次改动变色。
- 2D 降级路径用 `ctx.filter` 近似（仅在无 WebGL2 时走到）。
- 新增操作 `setClipEffect`：同类型**替换**而非叠加（调色是一组参数，不是滤镜链），可撤销。

## C1-3 音量与淡化（R-037）

- `envelopeAt(clip, offsetFrames)` 线性斜坡；淡入淡出同时存在取较小值。
- **音量与包络直接烘进 PCM**（`applyClipGain`），不用 `GainNode`：导出侧 `audioMix` 用同一套数学，
  两条链路若一条用节点、一条用逐样本，淡变段会产生可测差异。
- 播放侧按"块首尾增益线性插值"（对线性斜坡是精确的）；导出侧逐样本算
  （整段首尾插值在"跨过斜坡再进平台"时会算成 0→0 = 整段静音）。

## C1-4 顺手修掉的一个真 bug：`?src=` 打开时预览全黑

导入顺序是「`addAsset`（触发 doc 通知 → 渲染）→ `registerPreviewSource`」，
第一次渲染时源还没注册 → 取帧失败 → 合成器只清了屏，而且**不会再有下一次通知**来救它。
症状：`?src=` 打开全黑，随便点一下才出画。
修法：`renderPreviewFrame` 对"非精确帧"做**退避重试**（60/120/240/480/960ms，上限 5 次）。
为什么不用 rAF：实测解码会话建立 + 首个关键帧要 100–800ms，rAF 那几帧（16ms）全打在等待里。

# 批次 C2 交付记录（转场 + 入出点/区间导出）

## C2-1 转场（R-033）

**数据**：`Clip.transitionIn / transitionOut`（早就存在，这次真正用起来）。新操作 `setClipTransition`（可撤销，一次设置 = 1 步）。

**关键取舍：冻结帧溶解，不动时基**

PRD 要求"转场不吃掉接缝两侧内容"。真做"真素材溶解"需要 A 的出点之后、B 的入点之前还有素材（handle），
而 AI 生成片段首尾就是内容边界，硬向外取帧会越界——`mapProjectFrameToAssetFrame` 明确禁止返回区间外帧（T02 的教训）。

所以窗口**以接缝为中心** `[cut - D/2, cut + D/2)`：
- 前半段：A 正常播放，B 冻在首帧淡入；
- 后半段：A 冻在末帧淡出，B 正常播放。

每一侧有一半时间在放真实内容，另一半是冻结帧；时间线长度、两侧内容都不变，**零时基风险**。
代价是 0.5s 溶解里有一半静帧——短视频够用，真需要"双素材溶解"时再引入 handle 概念（要改 timebase 契约，单开一轮）。

**编排单独成文件**（`media/transitionPlan.ts`）：纯函数，能在 Node 里穷举"窗口前后一帧 / 无前序片段 / 隐藏轨"这些边界。

**交互**：属性栏「转场」组（无 / 交叉溶解 / 淡入 / 淡出 + 时长 0.1–2s）。
与 PRD 的"拖到接缝"有偏差：110px 属性栏里做下拉比在 8px 接缝上做拖拽热区更可靠，也不和裁剪手柄抢命中。

## C2-2 入出点与区间导出（R-040）

- `I` / `O` 打点，`Alt+I` 清除；标记存 `ephemeral`（会话级，不进撤销栈、不写盘）。
- 时间线绘制：区间外压暗 + 两条虚线 + 标尺上的「入 / 出」字样。
- 导出弹窗新增「仅导出标记区间」勾选（未打点时禁用并提示怎么打点）；时长与帧数随区间实时变。

## C2-3 又修一个真 bug：属性栏拿着过期的 clip

`InspectorPanel` 只订阅了"选中态"，改完属性后组件不重渲染，手里的 `clip` 还是旧对象。
症状：先设淡入再设淡出，淡入没被清掉（`{in:'fadeIn', out:'fadeOut'}`）。
修法：同时订阅 doc（`useDoc(d => d)`），clip 每次渲染从最新 doc 里取。
这也顺带修好了"撤销调色后滑块停在旧值"的同类问题。
