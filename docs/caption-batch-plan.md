## 1. 摸底结论（决定方案边界）

### 1.1 多选的数据层已经有了，但缺"批量设置"

| 能力 | 现状 | 位置 |
|---|---|---|
| 读选择集 | `store.getSelection(): string[]` ✓ | 内部是 `selectedClipId`（主）+ `extraSelectedClipIds[]`（次）|
| 加/减选 | `store.toggleSelection(id)` ✓ | Ctrl 点击用的就是它 |
| 单选（清多选） | `store.setSelectedClipId(id)` ✓ | 注释明确"清掉多选" |
| **批量设置** | ❌ **没有 `setSelection(ids)`** | 没有清空 API，也没有一次性设置 |
| 时间线的 Ctrl 加选 | ✓ 已实现（`pointerDown(..., { additive: ctrlKey \|\| metaKey })`）| `TimelineView.tsx:424` |
| 时间线的框选 | ❌ 未实现（P0 待办里那条）| — |

**这意味着**：Shift 范围选 / 框选**没有现成 API**，只能组合现有两个方法：

```ts
store.setSelectedClipId(null);        // 先清空（主选置空、次选清空）
for (const id of targetIds) store.toggleSelection(id);  // 逐个加
```

**代价**：N 次 `notify()`（N 次 React 重渲染）。24 条字幕的框选 = 24 次，实际可接受。

> **要不要加 `setSelection(ids)`？** 我倾向**先不加**（用户要求零底层改动）。
> 如果实测卡顿，再加一个原子方法（约 12 行，一次 notify）。这个取舍写在待确认 ①。

### 1.2 批量能力：三个纯函数已就绪，缺删除

| 操作 | 纯函数 | 状态 |
|---|---|---|
| 平移 | `buildShiftOps(clips, deltaFrames, doc)` | ✓ 已测（含"前移越界拒绝"）|
| 统一样式 | `buildBatchStyleOps(clips, patch)` | ✓ 已测（只改 patch 字段）|
| 合并 | `buildMergeOps(clips, doc)` | ✓ 已测（空格拼接 / 压到别人拒绝）|
| **删除** | — | ❌ **要补 `buildDeleteOps(clips)`**（就是循环 `removeClip`，~10 行）|

### 1.3 预设体系是两套，都要接

| 套 | 数据 | 应用到片段 |
|---|---|---|
| **模板库**（10 个内置标题样式）| `core/textPresets.ts` 的 `TEXT_PRESETS` | `presetToText(preset, content, {width,height})` → 完整 `TextContent` |
| **我的预设**（用户存的）| `persist/presets.ts` | `buildPresetOps(clip, preset)` → 已处理"文字样式走 `setClipText`、**保留内容**" |

**关键**：
- 模板批量套用要**保留各自文本** → `presetToText(preset, clip.text.content, size)`
- `presetAppliesTo(preset, clip)` 对文字片段恒为 `true`（`preset.ts:189`），不用额外过滤

## 2. 多选的触发方式与视觉

### 2.1 列表视图

| 操作 | 行为 | 实现 |
|---|---|---|
| 单击 | 单选（清空多选）+ 跳播放头 | `setSelectedClipId` + `onSeek` |
| **Ctrl/Cmd + 单击** | 加选 / 减选 | `toggleSelection` |
| **Shift + 单击** | **从锚点到目标的范围选**（替换当前选择）| 清空 + 循环 toggle |
| 双击 | 内联编辑（不变）| — |

**锚点（anchor）定义**：最近一次**普通单击**（或单选）的那条。
- 点第 3 条（锚点=3）→ Shift 点第 8 条 → 选中 3..8
- 点第 3 条 → Ctrl 点第 10 条（加选，**锚点不变**）→ Shift 点第 5 条 → 选中 3..5（不是 10..5）

> 这是资源管理器/剪映的通用规则。**锚点跟着普通点击走，不跟 toggle 走**。

### 2.2 时间轴视图

| 操作 | 行为 |
|---|---|
| 单击条块 | 单选 + 跳播放头 |
| Ctrl + 单击 | 加选 / 减选 |
| **空白处按下拖动** | **框选**：拖出矩形，命中"**与矩形相交**"的条块 |

**框选的判定规则（相交，不是包含）**：

```
块与矩形相交 ⇔ blockLeft < rectRight && rectLeft < blockRight
                 && blockTop < rectBottom && rectTop < blockBottom
```

**为什么用相交而不是包含**：用户从左往右拖时，起点通常在第一个块**内部**（块很窄时尤其如此）。
用"包含"的话，起点那个块永远选不中——用户会觉得"我从这儿开始拖的，它怎么没选上"。

**纵向范围**：字幕条块是单行的，所以纵向只要"矩形与轨道区域相交"即可，不必逐块比 Y。

### 2.3 视觉区分（三个维度互不冲突）

| 状态 | 视觉 | 说明 |
|---|---|---|
| **主选** | 蓝色实线左边条（`border-left: 2px solid accent`）| 已实现 |
| **次选（多选）** | **蓝色虚线左边条 + 略深底色** | 新增，与主选区分 |
| **播放高亮** | 浅色底（`data-active`）| 已实现，与选择无关 |

**多选计数**：工具条右侧显示「已选 3 条」（多选时替代「共 N 条」）。

> **为什么不给次选也用实线**：多选 20 条时满屏蓝条，看不出哪条是"主选"（主选决定属性栏显示谁）。
> 实线 vs 虚线是最小成本的可辨识差异。

## 3. 批量条（UI）

**多选（≥2 条）时**，工具条下方出现批量条：

```
┌──────────────────────────────────────────┐
│ 已选 3 条    [删除] [合并] [平移] [样式] [取消] │
└──────────────────────────────────────────┘
```

| 按钮 | 可用条件 | 行为 |
|---|---|---|
| **删除** | ≥1 条 | 删掉选中，一个撤销步 |
| **合并** | ≥2 条，且同轨 | `buildMergeOps`；失败（跨轨/压到别人）给中文提示 |
| **平移** | ≥1 条 | 展开输入行（见 §4）|
| **样式** | ≥1 条 | 展开样式面板（见 §5）|
| **取消** | — | 清空多选（`setSelectedClipId(null)`）|

**为什么用"展开"而不是弹窗**：左栏窄，弹窗会挡预览；展开行在面板内、可边看画面边调。

## 4. 批量平移（帧 / 秒双单位）

展开后是一行：

```
整体前移/后移： [ −0.5 ] [ 秒 ▾ ]   [ ← 前移 ]  [ 后移 → ]
```

- **单位下拉**：`秒` / `帧`（默认秒）
- **数值**：正数才有效；方向由按钮决定（不靠正负号，避免用户输入 `-5` 又点"前移"的歧义）
- 内部换算：`秒 → 帧` 走 `secondsToFrames(sec, fpsMilli)`（**时基唯一换算点**）
- 提交：`buildShiftOps(clips, deltaFrames, doc)`
  - 前移越界 → 拒绝并给中文提示（`不能前移 N 帧以上（第一条会跑到 0 之前）`）
  - 一次 dispatch = 一个撤销步

**边界**：平移只挪起点、不改时长（`buildShiftOps` 已保证）。

## 5. 批量样式（复用两套预设）

展开后是一列：

```
样式：
  模板   [字幕-白底] [字幕-黄字] [标题-大号] …
  我的   [我的预设A] [我的预设B] …
  ─────────────────────────────
  或直接调： 字号 [ 48 ] 颜色 [■] 对齐 [中]
```

- **模板**：`presetToText(preset, clip.text.content, {width, height})` → 保留各自文本、套用模板样式
- **我的预设**：`buildPresetOps(clip, preset)`（已处理保留内容）
- **直接调**：`buildBatchStyleOps(clips, { fontSize, color, align })`
- 全部：**一次 dispatch**（所有 clip 的 ops 拼在一起）

**尺寸换算**：模板按 1080p 设计，套到不同分辨率工程时要按 `{width, height}` 缩放
（`presetToText` 已内置，见 MEMORY「模板坐标必须按分辨率换算」）。

## 6. 单个撤销步（贯穿全部四项）

```ts
// 所有批量操作都是"收集全部 op，一次 dispatch"
const ops: ClipOperation[] = [];
for (const clip of clips) ops.push(...);
store.dispatch(ops, '批量删除字幕');   // ← 一次
```

**验证方式**（E2E）：批量操作后 `lastUndoLabel` 变一次，**按一次 Ctrl+Z 全部还原**。

## 9. 待确认（5 项）

### ① 要不要给 store 加 `setSelection(ids)`？

| 选项 | 好处 | 代价 |
|---|---|---|
| **A（推荐）先不加** | 零底层改动 | 框选 24 条 = 24 次 notify（实测应该无感）|
| B. 加一个原子方法 | 一次 notify，更干净 | 改 `store.ts`（约 12 行）|

**我倾向 A**，先量一下框选 100 条的耗时再决定。

### ② Shift 范围选要不要做？

列表里 Shift 范围选很自然（资源管理器/剪映都有），但时间轴视图里**框选更自然**。
- **A（推荐）**：列表做 Shift 范围 + 时间轴做框选（各取所长）
- **B**：只做 Ctrl 加选 + 框选（少一种交互）

### ③ 框选只做时间轴视图吗？

列表里"框选"（鼠标拖过一片行）不自然（会和滚动/双击冲突）。
- **A（推荐）**：只在时间轴视图做框选
- **B**：两边都做

### ④ 批量平移的输入形态

- **A（推荐）**：数值输入 + 方向按钮（`[0.5][秒▾][←前移][后移→]`）
- **B**：单个滑块（-5s ~ +5s，拖完松手提交）
- **C**：两个输入框（起点偏移 / 终点偏移）

A 最精确（用户知道要挪多少），B 最直观但精度差。

### ⑤ 批量样式的首选方式

- **A（推荐）**：给"模板 + 我的预设 + 直接调"三选一（都在展开行里）
- **B**：只给"套用当前主选的样式"（把主选的样式刷给其它条，类似格式刷）

**B 其实很实用**（"把这条的样式刷给其它"），但它不是"预设"。
**建议 A 为主 + B 作为一个快捷按钮「同主选样式」**（成本很低）。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 框选和"拖把手"抢事件 | 框选只从**轨道空白区**开始；把手 `stopPropagation`（已实现）|
| 多选 20 条时列表重渲染慢 | 选择集变化才重渲染（`useSelection` 走 store 订阅）；不订阅 doc 全量 |
| 批量操作选了跨轨的字幕 | 合并会拒绝（`buildMergeOps` 已检查轨）；删除/平移/样式**允许跨轨**（合理）|
| 用户不知道能框选 | 时间轴底部提示行加一句「空白处拖动可框选」|
| 模板套用后文本被清空 | `presetToText(preset, clip.text.content, ...)` 必须传原文本（单测守住）|
