## 2. 工程自动备份 + 历史版本回退：真实缺口，方案如下

### 2.1 现状与缺口

自动保存已存在：变更后 500ms 防抖写入 IndexedDB（`persist/autosave.ts`）。但 `saveProject` 是**单槽覆盖写**（`STORE_PROJECTS` 按 `project.id` 覆盖，`autosave.ts:85-99`）——只有"现在"，没有任何历史。页面崩溃前被覆盖掉的版本、误删轨道后想回到十分钟前，都做不到。

### 2.2 方案

**备份写入（`persist/backup.ts` 新模块）**

- 新 IndexedDB store：`STORE_PROJECT_BACKUPS = 'projectBackups'`（键 = `projectId|时间戳`，值 = 工程快照）。
  `db.ts` 的 `onupgradeneeded` 加一个 store——**schema 升级是幂等追加**，老工程打开不受影响。
- 触发时机：**定时**（默认每 5 分钟，可后续做成设置项）+ **回退前强制先拍一份**（防覆盖）。
  与现有 500ms 自动保存并行不悖：自动保存管"现在"，备份管"历史"。
- 滚动上限：每个工程默认保留 **20 份**，超出删最旧（IndexedDB 容量友好：一份工程 JSON 约几十至几百 KB）。
- 备份节流：距上一份快照内容无变化（比对 `updatedAt`/版本号）就不重复写。

**回退 UI（「工程」下拉 → 「历史版本…」）**

- 列表：时间 + 自动原因（如 `14:32 · 自动备份`、`14:35 · 回退前快照`），当前版本高亮。
- 恢复 = 载入快照 → 走**现有的工程载入路径**（与打开 .vedproj 文件同一条"替换当前 doc"的链路，不新写载入逻辑）；
  恢复前先对当前状态拍一份"回退前快照"（所以回退本身永远可撤销地反悔回去）。
- 入口在「工程」下拉（构建时间/缓存入口同一处），不动时间线。

### 2.3 边界与风险

- **不改现有 autosave 行为**：自动保存仍是 500ms 防钢单槽；备份是旁路。
- 备份只存工程 JSON（含片段/轨道/文本），**不含素材字节**——素材依赖现有五层恢复链路（草稿缓存/句柄/重链），快照恢复后素材缺失时走既有的"素材离线"提示。这点在回退列表的说明文案里写清楚。
- 大工程（几千片段）的快照写入是毫秒级 JSON 结构化克隆，不卡 UI（IDB 异步）。

### 2.4 测试设计

- Node 单测 `tests/backup.test.mjs`（fake IDB）：写入/列表/滚动上限删最旧/内容无变化跳过/回退前强制快照。
- E2E `verify-backup.mjs`：改 doc → 快进定时 → 列表出现 → 改动 doc → 恢复 → 内容回到快照点（工程摘要 hook 断言）+ 恢复前自动有"回退前快照"。
