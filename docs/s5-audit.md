## 二、缺口

### A. 真 bug（本轮已修 1 个）

#### A1. 跨轨拖拽用硬编码行高 —— 已修

```ts
// 修复前（pointerMove 里）
const hitTrackIndex = Math.floor((y - 24) / 56);
const targetTrack = trackDisplayOrder(doc.tracks)[hitTrackIndex];
const targetTrackId = targetTrack?.id ?? drag.fromTrackId;
```

- `56` 是 S1 之前的统一行高；S3 之后是**视频 60 / 音频 50 / 字幕 32**，而且**用户可以拖到 120**。
- 实测：把 V2 拖高到 120 后，从 V3 往 V2 拖会算出 `rows[2]`（V1）→ **落到 V1**。
- 更坏的是：如果算出的行号超出范围，会 fallback 到 `drag.fromTrackId`（原轨）——
  表现是"拖了完全没反应"，而且看起来像"拖了但没动"，极难归因。

**已修**：改用 `trackRowAtY(trackLayout(doc), y)`，实测 V3 → V2 正确落到 `trk_V2`。
顺带删掉了文件末尾 `TIMELINE_TRACK_HEIGHT = 56` 等三个 S1 遗留死常量。

### B. 完全没实现

| # | 缺口 | 现状 | 规范要求 |
|---|---|---|---|
| B1 | **框选（marquee）** | 空白处按下拖动，没有任何反应（探针：无选框元素） | §4.3 "框内所有片段全部选中"，判据用**相交**不用包含 |
| B2 | **Ctrl 加选** | `store.toggleSelection` / `getSelection` **有完整实现**，但 `pointerDown` 只调 `select()`，**UI 零调用点** —— 又是一处"数据层有、界面没接"（同 S4 的悬停态） | §4.3 |
| B3 | **多选后的批量操作** | 多选数据能存，但拖动只动主选、`Delete` 只删主选、`Shift+Delete` 也只删主选 | §4.3 "统一拖拽、统一删除、统一调整属性" |
| B4 | **时长气泡** | 拖动/裁剪时没有任何浮层（探针：无 `timeline-hint` 元素） | §4.1 "实时显示当前时长、起始时间、结束时间" |
| B5 | **跨轨指示线** | 拖到别的轨只有 ghost 块，没有"将落到这条轨"的横向指示 | §4.1 "出现横向指示线" |

### C. 半实现（有基础，缺一环）

| # | 缺口 | 现状 |
|---|---|---|
| C1 | **裁剪不吸附** | `snapFrame` 只在 `kind === 'move'` 分支被调用；`trim` 分支完全没有吸附 → 裁剪首尾贴不齐相邻片段，只能靠眼睛 |
| C2 | **磁吸目标缺"整数秒刻度"** | 只有 `0 / 播放头 / 片段边界`。规范要求概览态（zoom ≤ 6）加入整数秒 |
| C3 | **磁吸视觉只覆盖移动** | 吸附线画在拖动 ghost 上；裁剪时没有吸附线可看 |

### D. 可用性边界（实测踩到，值得单独说）

#### D1. 时间线可视区太小，多轨时跨轨拖拽很别扭

实测数据：默认 `--v-timeline-h: 220px`，扣掉工具栏（28）和标尺（24）后可视区约 **191px**。

- 3 条轨（V2 60 + V1 60 + A1 50 + 标尺 24）= 194px → **刚好装不下**
- 4 条轨、或把某条轨拖高到 120 → 314px → **上下两端不可能同时可见**

后果：跨轨拖拽必须先滚动，而**滚动会让起点或终点之一移出视口**（探针里滚到底后，顶部轨道被裁到容器外，鼠标事件直接落到工具栏上）。

这不是 S5 的"交互逻辑"问题，但它决定了"跨轨拖拽"的手感。两个方向：
- 拖到视口边缘时**自动滚动**（PR/剪映都有）；
- 或把默认时间线区域调高（比如 280px）。

#### D2. 拖到轨道区外（上下边界之外）

落在 `trackRowAtY` 返回 null 时 fallback 回原轨，**没有任何提示**。用户会以为"拖过去被拒绝了"，其实只是拖出了轨道区。

#### D3. 拖拽边缘不自动滚动

拖到画布左右边缘不会滚动，长项目要"松手 → 滚动 → 再拖"。

## 四、一句话结论

**基础拖拽/裁剪/磁吸/避让是扎实的**（10 项实测通过），
**缺的集中在"多选"和"反馈"两件事上**：多选（框选/Ctrl 加选/批量操作）全是"数据层有、界面没接"，
反馈（时长气泡/跨轨指示线/裁剪吸附）则是完全没做。

另外发现一个真 bug（跨轨硬编码行高）已修，以及一个容易被忽略的**可用性事实**：
时间线默认高度装不下 4 条轨，跨轨拖拽必须先滚动 —— 这让"自动滚动"从"锦上添花"变成 P2 里的优先项。
