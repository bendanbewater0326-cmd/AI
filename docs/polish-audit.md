## A. 技术术语（用户可见路径）

### A1【高】损坏文件的导入报错直接暴露内部结构词

- 定位：`media/demuxMp4.ts`（`'moov 解析失败'`/`'moov 内没有 trak'`/`'stsd 结构不完整'` 等 8 处）
  → `ui/AssetPanel.tsx:133` `pushError(result.error)` **原样透传**（`mapImportError` 只翻译
  `E_UNSUPPORTED_CONTAINER` 和 `E_UNSUPPORTED_VARIANT` 两类，`E_DECODE_FAILED` 不在翻译表里）。
- 用户看到的：「moov 解析失败」（moov/trak/stsd 是 MP4 盒子结构名，用户完全无法理解）。
- 修法：`mapImportError` 补 `E_DECODE_FAILED` 分支 →「这个文件无法读取，可能已损坏或不是标准
  MP4，请检查文件或重新导出一份」（内部词留在 detail 给诊断）。

### A2【低】IndexedDB 三条错误含"事务"技术词

- 定位：`persist/db.ts:113-122`（'IndexedDB 请求失败'/'IndexedDB 事务失败'/'IndexedDB 事务被中止'）。
- 判定：IndexedDB 本身用户勉强可懂（浏览器存储），"事务"是纯技术词。
- 修法：去掉"事务"——「本地存储读写失败，工程可能未能保存，请重试或清理浏览器存储空间」。

### A3【确认不动】detail 的小字弱化展示

- 定位：`ui/App.tsx:636` 错误条把 `error.detail` 以弱化样式（`v-errorbar__detail`）展示；
  CommandBar 4 处把 detail 拼进文案。
- 判定：**保留**。detail 是诊断信息（文件名/`assetFrame=239` 等），弱化小字展示是合理分层——
  主文案说人话、细节给较真的人看。全部中文化成本高且丢失诊断价值。

### A4【确认不动】SelfCheck / 宿主回执的英文

- 定位：`App.tsx:1349/1368`（selfCheck 诊断串）、宿主命令回执 detail。
- 判定：开发者向（用户拍板"面向开发者的输出保持原样"）。

## C. 操作反馈闭环

### C1【高·最大缺口】busyLabel 有 33 处写入、零处渲染

- 定位：`core/store.ts:883` 写入；**全仓无任何 UI 读 `busyLabel`**（grep 仅 types 定义与 store 写入）。
- 影响：素材导入「正在解析素材…」、右键导出音频「正在导出音频… 37%」、工程包「正在收集素材…」、
  重链、vedpack 导入「正在打开工程包…」等**全部进行中状态从未显示**——异步操作期间界面无任何反馈，
  用户只能靠猜。这是又一处"数据层有、界面没接"（同 S4 悬停态 / Ctrl 加选）。
- 修法：顶部加一条 **busy 条**（渲染 `ephemeral.busyLabel`，样式对齐现有错误条 `v-errorbar`，
  `role="status"` + `aria-busy`），App 挂一次即全链路生效——33 处调用零改动。

### C2【确认不动】高频添加类操作的成功 toast

- 音效/文字/转场/特效的点击应用是**同步即时可见**（片段落轨、高亮切换本身就是反馈），
  再加 toast 是噪音。判定：不加。

### C3【已合规】字幕面板

- `flash()` 成功提示（「已生成 N 条字幕」）+ busy 态按钮文案切换，三态齐全，是其它面板的范本。
