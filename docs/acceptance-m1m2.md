# M1 + M2 验收用例清单（R-001 ~ R-032）

- 适用：M1「能跑」+ M2「能剪」交付验收，覆盖 **32 条 P0 需求**
- 配套：`PRD.md`（需求口径）、`frame-clock-spec.md`（时基权威）、`architecture.md`（任务与实现）
- 引用约定：`spec:T7` = 时基规格第 7 号用例；`task:T17` = 架构任务 T17

---

## 0. 怎么用这张表

| 角色 | 用法 |
|---|---|
| team-lead | 只点第 3 节列出的「必须亲自点的 5 条」，其余看脚本输出与本节第 2 表 |
| software-engineer | 交付前把第 2 节所有「自动」项跑绿，并把输出存到 `tests/reports/` |
| 复验 | 任一条判据不满足即整条不通过，**不允许"基本满足"** |

**证据类型仅限五种**：`截图` / `录屏` / `控制台输出` / `测试文件输出` / `IndexedDB 快照`。出现第六种（如"口头说明""感觉正常"）视为未提供证据。

## 4. 最容易被假装通过的方式（逐条）

| ID | 常见糊弄方式 | 反制（验收时只认这个） |
|---|---|---|
| R-001 | 只改顶栏文案，`doc` 里 fps 没变 | 查 IDB `fpsMilli/width`，不看顶栏显示 |
| R-002 | 只测拖拽一个入口；用小文件让 3 秒轻松过 | 三个入口各测 + 100MB 文件计时打印 |
| R-003 | 用 `canvas.toDataURL()` 画个渐变或模糊占位冒充缩略图 | 与 `ref_000.png` 缩到 90×51 后**逐像素比 + 8×8 分块**：平均 ≤ 15、每块 ≤ 35。纯色/渐变会在多数分块上远超阈值；"只是非纯色"不再算过 |
| R-004 | 只在 Chromium 跑，从不触发降级路径 | 强制禁用 FS Access 或 Safari 跑一次 |
| R-005 | 看"时间线上出现了一块"就算过 | 断言 `startFrame == playheadFrame`、`durationFrames` 精确相等 |
| R-006 | 有声音、画面在动就算过 | 20 次采样对齐 `audioFrame/currentFrame`，每次 ≤ 1 帧 |
| R-007 | 只按两下 `→` 看到画面变了 | 帧序列与期望数组逐项相等，含首尾停住 |
| R-008 | "拖动后画面变了"就算过 | 帧号必须 == 目标；与 `ref_longgop_137.png`（640×360，尺寸与素材一致）逐像素比 |
| R-009 | 时间码长得像时间码就算过 | 正则 + 第 137 帧必须 == `00:00:04:17` |
| R-010 | 只看最常用的一档缩放 | 三档都要，且量像素间距 |
| R-011 | 播放头在动就算过 | `abs(playheadX − frame×zoom) ≤ 1px` |
| R-012 | 块画出来了就算过 | 宽度误差 ≤ 1px + 块内缩略图方差 > 阈值 |
| R-013 | 刷新后能看到片段就算过 | 六字段深度相等，含 `zoomLevel` 与 `playheadFrame` |
| R-014 | 空态里多放几个按钮也算"有引导" | 只能有一个动作，多一个即不通过 |

| R-017 | 片段消失就算过 | 其他片段 `startFrame` 必须不变（区分删除 vs 波纹） |

| R-019 | 松手后位置像对了 | 整数帧 + 与同轨无重叠 + 落在最近合法位置 |

## 5. 四条生死线的硬性脚本要求

> 这四条**不接受人工确认**，必须由脚本给数值。脚本放在 `tests/`，输出 JSON 到 `tests/reports/`。

### 5.1 R-008 seek 帧精确

| 项 | 要求 |
|---|---|
| 数据 | `hardline/longgop.mp4`（640×360 / 240 帧 / **仅 1 个关键帧**）+ `ref_longgop_137.png`（640×360）。**尺寸必须与素材一致，不能拿 1280×720 的 `ref_137.png`** |
| 调用 | `__VEDITOR_TEST__.renderFrame(137)` → 等首个 `exact===true` → `captureFrame()` 取 RGBA |
| 断言 ① | `currentFrame() === 137`（容差 **0 帧**） |
| 断言 ② | 与 `ref_longgop_137.png`：**平均通道差 ≤ 15** 且 **PSNR ≥ 20dB**（**已实测定案**，跨渲染链路；单通道最大差仅记录、不设阈值。依据见 `hardline-test-spec` §5 与 `architecture.md` 附录 B.1） |
| 断言 ③ | 随机 50 次 seek（间隔 > 30 帧）：每次 `currentFrame() === target` 且 `exact===true`，失败 0 次 |
| 断言 ④ | 同一组用例对 **webm 素材**再跑一遍（task:T19 交付后必须同样全绿） |
| 断言 ⑤ | 耗时按 PRD §9 分档：回退 ≤ 15 帧 → ≤ 100ms；回退 > 15 帧 → **`≤800ms`（绝对上限，永不放宽）且 `≤3×应用内基线`**（基线 = `decoderPool` 顺序全解 240 帧，同机现场测；`ffmpeg` 耗时仅参考），期间显示"定位中"。判定按 `hardline-test-spec` §5.1 四情况表：**`>800ms` 但 `≤3×基线` 记"环境受限、不算失败"**（须记录基线值并在基准机复测），其余超限判不通过。**不得为过验收把结果换成最近关键帧** |
| 反例保护 | 若实现"回到最近关键帧继续播放到目标"，必须证明最终帧 == 目标帧，而不是"接近" |

> **像素判据（已实测定案 2025-10-20，作废 `≤2 / ≤0.5 / ≥40dB`）**：断言② = **平均通道差 ≤ 15 且 PSNR ≥ 20dB**，**单通道最大差不设阈值**（仅记录进报告 JSON）。这是**跨渲染链路**比对：`ref_longgop_137.png` 由 ffmpeg 从 `yuv420p` 抽出，被测值来自 WebCodecs 解码 → Canvas/WebGL 合成 → `getImageData`，两条链路各做一次 YUV→RGB，矩阵（BT.601/709）与重采样实现不同，**"实现完全正确"也不可能是 0**。
> **实测数据与分离度**：跨链路噪声 **平均差 8.75–10.34 / PSNR 26–27dB**（2025-10-20，Chrome+WebCodecs vs ffmpeg swscale）；**错一帧 17.11–17.86dB（≈26）**；错很远 13.13dB（≈45）。换算 `RMSE = 255/10^(PSNR/20)`、`平均差 ≈ 0.8×RMSE`。
> **为什么不取 25dB**：离噪声 26–27dB 只有 1–2dB，机器抖动即假红；20dB 落在下半区，**必须稳定抓住错帧、稳定放过跨链路噪声**。**反例线**（"不得停在旧帧/不得残留首末帧"）取 **平均差 > 20**——`15 < 20 < 26`，与通过线不重叠、也不压着噪声（噪声 ≤10.34），原来的 `> 10` 与通过线重叠已作废。
> 若实测落在 20–27dB 灰区：**先排查色彩空间**（`VideoFrame.colorSpace` vs ffmpeg `colorspace`/`color_primaries`/`color_transfer`），确认矩阵一致后才允许按留档流程调整。**同链路同源比对**（`captureFrame()` vs 上屏、缩略图位图 vs 重算位图）**仍保持 `maxCh ≤ 2 / ≤ 0.5`，不受本条款影响**。

## 7. 验收口径补充（三条，需实现与验收一致）

1. **切分 no-op**：切点落在片段首帧或末帧时，不产生任何操作、不进撤销栈（避免出现 0 帧片段污染数据）。此条已写入本文 §5.2 断言⑤，实现需在 `splitClip` 内先判边界。
2. **"部分通过"的记账方式**：M2 阶段 R-031 / R-032 各有一条子项属 M3（导出 PSNR、封装时长）。验收单必须写「M2 部分通过（子项：…）+ 待 M3 补验」，**不得直接勾"通过"**，否则 M3 会丢失这两条。
3. **性能口径**：性能不作为单条需求的验收项，但四条生死线脚本必须同时记录耗时，超预算即视为回归（例：`renderFrame` 连续 100 帧平均 < 3ms；seek 按 PRD §9 两档：回退 ≤ 15 帧 ≤ 100ms、回退 > 15 帧 ≤ 800ms 且显示"定位中"）。**性能可分档，正确性不可分档**。
4. **R-019「最近合法位置」的定义**（PRD 原文只写"最近"，验收需要可判定值）：松手位置与同轨已有片段重叠时，取左右两侧可用空间中的**距离更近者**；两侧距离相等时**取右侧**（向右避让不改变与左侧片段的相对顺序，更符合直觉）。验收时记录 `落点帧号`，与该定义算出的期望值比对，必须相等。
