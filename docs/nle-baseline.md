# 常规剪辑软件行为基线（我们照着做，以及有意偏离的地方）

> 起因：2026-10-22 用户反馈——
> "删除音频等这些功能不是一次性，不是你使用过就无法继续使用的了……
> 我希望你能够更智能一点，更能理解一下常规剪辑软件是怎么样的。
> 我觉得你现在首要目标是先去了解常规剪辑软件是什么样的，再来协助我制作。"
>
> 这份文档就是那个"先去了解"。它回答两件事：
> 1. 常规软件（剪映专业版 / CapCut / Premiere Pro / Final Cut）**在这些基础功能上到底怎么表现**；
> 2. 我们**照做**还是**有意偏离**，以及为什么。

---

## 0. 一条压倒性原则：**状态派生，不记历史**

用户报的那个 bug 是这条原则的反例：

```
分离音频 → 删掉分离出来的音频片段 → 再点"分离音频" → "音频已经分离过了"（永远）
```

错在把"分离过"记成了 `clip.role === 'video'` —— **用历史动作当状态**。
正确的问法是"**现在**这段素材的声音在时间线上吗？"：
有 → 拦（否则叠出第二份）；没有 → 允许（从源素材再造一份）。

这条原则适用于所有功能。每次加一个"用过了"的判断，都要问一句：
**这个判断看的是当前状态，还是历史动作？**

| 看起来像"用过就不能再用"的功能 | 正确的派生判据 |
|---|---|
| 分离音频 | 时间线上还有没有同源的音频片段 |
| 删除音频（只留画面） | 同上（`role` 只说明"不出声"，不说明声音在哪） |
| 静音 | `audio.gain === 0`，随时可调回 |
| 隐藏 / 锁定 | 布尔开关，随时可切回 |
| 定格 / 倒放 | 生成的是**普通片段**（带标记），删掉就没了，随时可再做 |
| 字幕整段替换 | 旧 cue 随撤销栈回来 |

## 1. 音画分离与删除

| 行为 | 剪映 / CapCut | Premiere Pro | 我们 |
|---|---|---|---|
| 分离音频 | 右键「分离音频」→ 声音落到下方新音频轨，画面片段变静音 | 右键「Detach Audio」→ 音频落到新音轨 | 同（`Clip.role`） |
| 分离后拖动 | 两段独立，可分别拖/裁/删 | 同（默认仍"链接"，一起选中；`Ctrl+L` 可断开） | 两段**完全独立**（比 PR 更松，但没有链接选择概念） |
| 删除分离出的音频 | 声音消失，**不能**再次分离（只能撤销） | 同（视频片段上已经没有音频可分离） | **允许再次分离**（有意偏离，见下） |
| 删除音频（只留画面） | 没有单独的菜单项，等价于"分离后删音频" | 同 | 有单独菜单项（`role='video'`，声音彻底不参与） |
| 静音 | 有（音量 0），可恢复 | 有（Mute） | 有（`audio.gain=0`，可恢复） |

**有意偏离（唯一一处）**：删掉分离出来的音频后，我们允许**重新分离**。

理由：我们的画面片段始终持有 `assetId`，声音随时能从源素材重新解出来；
而剪映/PR 把"分离"实现成"把音频搬走"，搬走再删就真的没了。
用户要的是"功能不是一次性的"，而且"重新分离"不会凭空造出不存在的东西——
它只是把源素材里的声音再取一次。**代价**是必须防止叠出第二份，所以判据是
"时间线上还有没有同源的音频片段"（同 `assetId` + 源区间相交，拖走/裁短都还算数）。

## 2. 定格帧（Freeze Frame）

| 项 | 剪映 | PR | 我们 |
|---|---|---|---|
| 入口 | 右键「定格」/ 基础编辑 → 定格 | 右键「Add Frame Hold」/ 导出帧再导入 | 右键「定格」 |
| 落点 | 播放头处**插入**，原片段被切开 | 同 | 同 |
| 默认时长 | **3 秒** | 由 `Frame Hold Options` 决定 | **3 秒**（与剪映一致） |
| 之后可改吗 | 可当普通片段拉伸/裁短 | 可 | 可（是普通片段 + `freezeFrame` 标记） |

**实现口径**：定格帧 = 在播放头把原片段切成两半，中间插入一个**只含 1 帧源素材**的片段，
拉伸到 3 秒（`speedMilli` 保持 1000，靠 `inFrame/outFrame` 都是那一帧 + 渲染时重复该帧）。
这样它天然能被拖、被裁、被删、被撤销——不需要新概念。

## 3. 倒放（Reverse）

| 项 | 剪映 | PR | 我们 |
|---|---|---|---|
| 入口 | 右键「倒放」 | 右键「Speed/Duration → Reverse」或效果 `Time Remapping` | 右键「倒放」 |
| 音频 | 一起倒放 | 一起倒放 | **只倒画面，声音保持原样**（见下） |
| 可撤销 | 是 | 是 | 是（`Clip.reversed` 布尔） |

**有意偏离**：只倒画面，不倒声音。

理由：倒放人声会变成完全听不懂的怪声，而我们的音频路径是"按样本区间解码"，
倒放音频要整段重采样进内存（长片段直接把内存打满）。
用户真实需求 99% 是"倒放一个动作镜头"，画面倒放即可；需要倒放声音时属于特效，不在基础功能内。
**这条要在右键菜单里写清楚**：`倒放（只倒画面）`。

**实现口径**：`Clip.reversed = true` 时，`mapProjectFrameToAssetFrame` 里把
"片段内偏移"翻转成 `durationFrames - 1 - offset`，于是取到源素材的对称帧。
渲染、导出、缩略图全部走同一个换算入口，天然一致；**解码器仍然顺序读**（不需要反向解码），
只是读到的帧被放到相反的时间点上——这一点很关键：反向解码会慢到不可用。

## 4. 逐帧步进

| 键 | 剪映 | PR | 我们 |
|---|---|---|---|
| `←` / `→` | 上一帧 / 下一帧 | 同 | 同 |
| `Shift + ←` / `Shift + →` | — | **5 帧** | **10 帧**（有意偏离，见下） |
| `Home` / `End` | 片段头/尾（无选中时序列头/尾） | 同 | 同 |

理由：逐帧是"对齐口型/对齐鼓点"的刚需，鼠标拖永远差一两帧。

**有意偏离**：大跳我们给 **10 帧**（30fps 下正好 1/3 秒）而不是 PR 的 5 帧。
短视频素材基本都是 30/60fps，10 帧更接近"一秒的几分之一"的直觉；
真要 5 帧连按两下就行。

## 5. 吸附（Snapping）

| 项 | 剪映 | PR | 我们 |
|---|---|---|---|
| 默认 | 开 | 开 | **开** |
| 开关 | 时间线右上角按钮 / **`N`** | 时间线按钮 / **`S`** | 时间线工具栏按钮 + **`N`**（跟剪映，中文用户更熟） |
| 吸附目标 | 其他片段首尾、播放头、时间线 0 点 | 同 | 同 |
| 吸附距离 | 约 8–10px | 约 10px | **8px**（`SNAP_THRESHOLD_PX`，按 zoom 换算成帧） |

关键细节（剪映也这么做）：**吸附只在拖动时生效，不影响键盘/数值输入**；
按住 `Alt` 临时关闭吸附（PR 的习惯，剪映是 `Ctrl`，我们跟 PR 的 `Alt`，因为 `Ctrl` 在时间线上已用于多选/缩放）。

## 6. 旋转与翻转

| 项 | 剪映 | PR | 我们 |
|---|---|---|---|
| 旋转 90° | 有（每次 90°，累计） | 有（任意角度 + 90° 按钮） | **90° 步进**（`clip.transform.rotation` 0/90/180/270） |
| 水平翻转（镜像） | 有 | `Flip Horizontal` | 有 |
| 垂直翻转 | 有 | `Flip Vertical` | 有 |
| 任意角度 | 有（旋转滑块） | 有 | **不做**（见下） |

**有意偏离**：只做 90° 步进 + 翻转，不做任意角度。

理由：任意角度会引入**画面外黑边**（用户第一反应是"怎么有黑边"，剪映是自动放大裁切，
而"自动放大多少"是个产品决策，容易做得很糟）。90° 步进 + 翻转覆盖了 95% 的真实需求
（手机竖拍、镜像自拍），且不会产生黑边。需要微调角度时用"位置/缩放"。

**与素材旋转的区别**：`Asset.rotation` 是**容器元数据**（手机拍的 270° 要自动转正），
`Clip.transform.rotation` 是**用户意图**。两者叠加顺序：先容器旋转（自动转正），
再用户旋转（90° 步进），最后翻转。顺序写死在一个函数里，渲染与导出共用。

## 8. 原计划的顺序（留档）

1. **分离音频可重来**（bug，已修，12 单测）
2. 旋转 90° + 水平/垂直翻转（属性栏 + 右键）
3. 逐帧步进（`←/→`、`Shift+←/→`）
4. 吸附（默认开，`N` 切换，`Alt` 临时关）
5. 定格帧（3 秒）
6. 倒放（只倒画面）

每一项都要有：单测（纯逻辑）+ E2E（真实 UI 路径，不许用测试钩子抄近路）。
