# 新手引导方案

> 状态：**待确认**（2026-10-25 摸底完成）
> 目标：让新用户第一次打开就知道「从哪开始、怎么做出第一支片」
> 边界：**纯 UI 浮层**，不碰任何业务逻辑 / 数据结构 / 渲染链路

---

## 1. 摸底结论（6 个锚点全部可定位）

| 步 | 目标 | 选择器 | 稳定性 |
|---|---|---|---|
| ① 功能面板 | 左栏图标条 | `[data-v="left-tab-media"]` | ✅ 常驻 |
| ② 素材导入 | 素材栏整体 | `[data-v="asset-content"]` | ✅ 常驻 |
| ③ 时间轴 | 时间线区域 | `[data-v="timeline"]` | ✅ 常驻 |
| ④ 属性调节 | 右侧属性栏 | `[data-v="inspector-panel"]` | ✅ 常驻 |
| ⑤ 导出 | 顶栏导出按钮 | `[data-v="export-open"]` | ✅ 常驻 |
| ⑥ AI 能力 | 顶栏 AI 入口 | `[data-v="ai-open"]` | ✅ 常驻 |

**关键取舍**：② 我**没有**用 `[data-v="asset-empty"]`（空状态那块引导区）。
它只在"没有素材"时存在 —— 用户先导入了素材再触发引导（比如从设置面板手动唤起），
那一步就会指空。用 `asset-content`（整栏外壳）任何时候都在。

**已有可复用模式**：`ContextMenu` / `TimelineView` 都用 `createPortal` 挂到 body，
引导也走同一套（避免被左栏的 `overflow: hidden` 裁掉）。

## 2. 视觉实现（不用 4 块蒙层，用 box-shadow 挖洞）

```
<div class="onboarding" (fixed inset:0, pointer-events:auto, onClick=关闭)>
  <div class="onboarding__spotlight" (pointer-events:none,
       box-shadow: 0 0 0 9999px rgba(0,0,0,.62)) />
  <div class="onboarding__tip" (pointer-events:auto, onClick=stopPropagation) />
</div>
```

**为什么用 `box-shadow` 而不是四块拼接 / `clip-path`**：
- 四块拼接要算 8 个坐标，窗口一改就要重算，容易出缝
- `clip-path` 在部分环境有抗锯齿毛边
- **一个 div + 超大投影**：位置一变只改 `left/top/width/height` 四个值，永远无缝隙

**目标为什么能点**：`spotlight` 是 `pointer-events: none`，
鼠标事件穿透到下面真实的目标元素 —— **引导期间用户可以真的去点、去拖**。

**点空白为什么能关**：外层容器 `pointer-events: auto`。
点目标时事件落到目标元素（不在容器子树里，不会冒泡到容器），所以**不会误关**。

## 3. 步骤内容（6 步，文案按新手认知写）

| # | 标题 | 正文（初稿） | 落点 |
|---|---|---|---|
| 1 | 左边这些是功能区 | 素材、文本、音频、转场、特效、字幕、调节、设置都在这儿。做片从「素材」开始。 | 左栏图标条右侧 |
| 2 | 先把素材放进来 | 两种方式：**把视频/图片直接拖进窗口**，或者点素材栏里的「导入」。 | 素材栏右侧 |
| 3 | 这里是时间轴 | 片段按时间从左到右排开。拖动它换位置、拖两端改长短，**右键**能切分、删除、分离音频。 | 时间轴上方 |
| 4 | 选中片段后，右边能调 | 点一下片段，右边就会出现它的属性：位置、大小、不透明、颜色、声音。 | 属性栏左侧 |
| 5 | 满意了就导出 | 点「导出」，选个规格（竖屏短视频 / 1080P / 720P），改个文件名就行。 | 导出按钮下方 |
| 6 | 还能直接说人话 | 按 **Ctrl + K**（Mac 是 ⌘ + K）说「把亮度调低点」「自动生成字幕」，它会自己动手。 | AI 入口下方 |

**位置策略**：`tip` 相对于 spotlight 自动摆 —— 目标在左半屏放右边、右半屏放左边；
空间不够时放上方/下方。规则写在 `steps.ts` 的 `placement` 字段（`right` / `left` / `below` / `above`），
不靠运行时瞎猜（每一步我都知道目标在哪一片）。

**第 3 步的文案注意**：空工程时时间轴是空的，不能写"拖动这个片段"——
写成"片段按时间排开…（导入后就会出现）"，**描述位置而非指着某个具体片段**。

## 4. 交互与状态

### 4.1 触发

| 场景 | 行为 |
|---|---|
| 首次打开（localStorage 无标记） | 页面**加载完成 + 300ms 后**自动启动（等首帧渲染稳定，否则 rect 算出来是 0）|
| 已完成 / 已跳过 | **不再自动弹** |
| 设置面板「重新查看新手引导」 | 手动唤起（不看标记）|

### 4.2 退出（三种都支持）

- 点「跳过」（底部链接）
- `Esc`
- 点蒙层空白处

**完成和跳过都写标记**，区别只在于事后统计（都算"看过了"）。

### 4.3 步进

- 「下一步」/「上一步」
- 键盘：`→` / `Enter` 下一步，`←` 上一步，`Esc` 退出
- 第 1 步不显示「上一步」，第 6 步按钮变「开始创作」

### 4.4 状态存储

**独立 key**：`localStorage['veditor:onboarding']`，值 `'done'` 或 `'skipped'`

**为什么不复用 `veditor:prefs`**：prefs 是"用户偏好"（默认时长、吸附），
引导进度是**一次性状态机**，混在一起会让 prefs 的语义变浑。

**为什么不用 `doc`**：换工程不该重新弹引导。

**不做版本号**：内容以后改了也不让老用户再看（用户明确"不重复打扰"）。
需要时靠设置面板手动唤起。

## 5. 容错

| 情况 | 处理 |
|---|---|
| 目标元素不存在（`querySelector` 返回 null） | **跳过该步**，自动找下一个有效步；全都没了就静默关闭 |
| 目标尺寸为 0（`display:none` 的 Tab 内容） | 同上按"不存在"处理 |
| 窗口缩放 / 滚动 | `resize` + `scroll`（捕获阶段）重算 rect；`requestAnimationFrame` 合帧，避免连续 resize 抖动 |
| 引导期间用户拖了时间轴 / 换了 Tab | 同上，rect 实时跟随（不打断引导）|
| 用户在引导里点了目标（比如真的导入了素材） | 不拦，引导留在原步；下一步的 rect 已经更新 |

## 8. 待确认（4 项）

### ① 引导期间，用户能否真的操作目标？

- **A（推荐）能**：spotlight `pointer-events: none`，用户可以直接点导入按钮、拖片段。
  引导不拦，用户边看边试。
- B. 不能：全屏拦截，逼用户先看完。

A 更符合"轻量化"定位，且第 2 步（导入素材）天然需要用户真去点。

### ② 点目标区域是否自动进下一步？

- **A（推荐）不自动**：用户自己点「下一步」。自动跳会让人措手不及（正在读字就被跳走）。
- B. 自动：点一下就进下一步。

### ③ 自动触发的时机

- **A（推荐）首帧后 300ms**：等布局稳定，否则 `getBoundingClientRect` 可能算出 0 宽。
- B. `load` 事件立即弹。

### ④ 空工程时第 3 步（时间轴）怎么讲？

- **A（推荐）**：文案写"片段按时间排开（导入后会出现）"，指着**容器**而不是具体片段。
- B. 空工程时跳过这一步。

A 更好：用户需要知道**这块区域是干什么的**，哪怕现在是空的。

## 9. 验收标准

| 项 | 标准 |
|---|---|
| 零回归 | `npm test` 795 条全绿；75 个 E2E 全绿 |
| 首次触发 | 清 localStorage → 刷新 → 引导自动出现 |
| 不重复打扰 | 完成/跳过后再刷新 → 不出现 |
| 三种退出 | 跳过按钮 / Esc / 点空白 都能关 |
| 步进 | 6 步走完；`←`/`→` 可切换；第 6 步按钮是「开始创作」|
| 高亮跟随 | 改窗口大小 → spotlight 跟着目标走（误差 ≤ 2px）|
| 容错 | 目标不存在时自动跳过，不指空 |
| 可操作 | 引导期间能点目标（如导入按钮）|
| 文案 | 全中文，无技术术语 |
