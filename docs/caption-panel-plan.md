# 左栏「字幕」面板方案

> 状态：**待确认**（2026-10-23 摸底完成，等用户拍板后开工）
> 前置：`subtitle/srt.ts`（解析/序列化/落轨）、`ai/transcribe.ts`（转写链路）均已就绪
> 目标：**只做上层 UI 封装**，底层字幕能力零改动

---

## 1. 摸底结论（决定方案边界的事实）

### 1.1 底层能力已经完整，缺的只是"管理界面"

| 能力 | 实现 | 位置 |
|---|---|---|
| SRT 解析 | `parseSrt(text)` → `{ cues, skipped }`（容错：坏块跳过并计数） | `subtitle/srt.ts:61` |
| SRT 序列化 | `serializeSrt(cues)` | `:99` |
| 重叠消解 | `resolveCueOverlaps(cues)` → 截短尾巴 + `truncated` 计数 | `:184` |
| 落轨（整段替换）| `buildSubtitleReplaceOps(cues, doc)` → 一个撤销步 | `:229` |
| 从工程提取字幕 | `extractSubtitles(doc)` → 按起点排序 | `:255` |
| AI 转写 | `transcribeTimeline({ doc, transcribe, language })` | `ai/transcribe.ts:120` |
| 转写结果清洗 | 过滤 `endSec <= startSec` / 乱序 / 空白 | 同上 |

### 1.2 落轨已经统一（用户要求 ③ 已满足）

**字幕与手动添加的文字落在同一条 `text` 轨**（`core/placement.textTrackFor`）。
这不是新工作——`srt.ts:229` 的注释记录了修复：

> 2026-10-23 之前这里找的是"最上面的视频轨"，于是手动加的字在 T1、导入的字幕在 V2，
> 用户会以为"字幕没导进来"（两条轨在时间线上离得很远）。

**现状**：`TrackKind = 'video' | 'audio' | 'text'`，字幕走 `textTrackFor` ✓

> ⚠️ 唯一遗留：`buildSubtitleClips` 的 `SubtitlePlacement.trackId` 注释还写着
> "落哪条视频轨（通常是最上面那条）"——**注释过期**，实现已改成文字轨。方案里顺手修正。

### 1.3 现有 UI 入口分散在两处

| 入口 | 位置 | 行为 |
|---|---|---|
| 导入 SRT | **顶栏**（`TopBar`，文件选择） | `parseSrt` → `buildSubtitleReplaceOps` → 一个撤销步 |
| 导出 SRT | **顶栏** | `extractSubtitles` → `serializeSrt` → 下载 |
| 自动字幕 | **命令栏**（`Cmd+K` 说"自动生成字幕"） | 需要宿主 `transcribe` 通道，没有则给可读拒绝 |

**没有"字幕列表"** —— 用户导入 30 条字幕后，只能去时间线上一条条点（T1 轨挤满小片段）。

### 1.4 多选能力已具备（S5 产物）

`store.getSelection() / toggleSelection() / setSelection()` 已实现，
批量操作有现成基础（不必新建选择模型）。

### 1.5 字幕的判据是全项目统一的

`clip.text !== null && clip.text !== undefined` —— 5 处代码都用这个判据
（`effectTarget` / `preset` / `playbackEngine`）。**字幕面板也必须用它**，不能自创。

## 2. 定位与分工

| 面板 | 职责 | 典型用法 |
|---|---|---|
| **文本**（已有） | 加**独立文字**：标题、花字、模板库 | "在开头加个大标题" |
| **字幕**（本方案） | 管理**整条字幕轨**：列表、批量、导入导出、转写 | "把整段口播的字幕对一遍" |

**数据同源**（都是 `clip.text` + `text` 轨），区别是**入口与批量能力**。
在文本面板加的字会出现在字幕列表里（方案里会标注来源），反之亦然——**不制造第二份数据**。

## 3. 面板结构

### 3.1 顶部工具条

```
┌─ 字幕（12 条）────────────────────────┐
│ [ 列表 | 时间轴 ]   [＋ 自动字幕] [导入] [导出] │
└───────────────────────────────────────┘
```

- **视图切换**：列表 / 时间轴（用户要求 ①）
- **＋ 自动字幕**：调 `transcribeTimeline`；宿主无 `transcribe` 时**禁用 + 一行说明**（不静默失败）
- **导入**：文件选择 → 复用顶栏那条实现
- **导出**：`extractSubtitles` → 下载 `.srt`

### 3.2 列表视图（默认）

```
┌───────────────────────────────────────┐
│ #1  00:00:00.00 → 00:00:02.50        │  ← 点时间码可编辑
│     大家好，今天聊聊剪辑          [✎] │  ← 双击文本内联编辑
├───────────────────────────────────────┤
│ #2  00:00:02.50 → 00:00:05.20        │
│     第一个技巧是……               [✎] │
└───────────────────────────────────────┘
```

- **点击一条** → 播放头跳到该条起点 + 选中该片段（与时间线双向联动）
- **双击文本** → 内联编辑（`Enter` 提交 = 一个撤销步；`Esc` 取消）
- **点时间码** → 可编辑起止时间（`HH:MM:SS.mmm`，超范围/重叠给提示而不是静默改）
- **当前播放位置所在的字幕**高亮（播放时能看出"现在念到哪句"）
- **来源标注**：手动添加的文字显示「文字」角标（因为同源，用户需要区分）

### 3.3 时间轴视图

按时间比例横向画条块（迷你时间线）：

```
00:00      00:10      00:20      00:30
├──────────┼──────────┼──────────┤
│███ 大家好 ███│  ███ 第一个技巧 ███│
```

- 点条块 → 选中对应片段
- 拖条块两端 → 改起止时间（复用 `trimClip`，**不新写拖拽逻辑**）
- 当前播放头画一条竖线

> **为什么两个视图都要**：列表适合"逐条对文本"，时间轴适合"看节奏/查空隙"。
> 只给一个都会有用户觉得别扭。

### 3.4 批量编辑

顶部工具条在**多选时**出现批量操作：

| 操作 | 说明 |
|---|---|
| 批量改样式 | 字号 / 颜色 / 对齐（一次 dispatch = 一个撤销步） |
| 批量删除 | 删掉选中的字幕 |
| 批量平移 | 整体前移/后移 N 帧（对齐用） |
| 合并 | 把选中的连续几条合成一条（文本用空格拼接） |

**多选交互**：`Ctrl/Cmd + 点击`切换选中、`Shift + 点击`范围选择（复用 `toggleSelection`/`setSelection`）。

## 4. 与时间线/播放头的联动（关键）

字幕面板不是独立世界，三处必须联动：

| 动作 | 结果 |
|---|---|
| 列表点一条 | 播放头 → 该条起点；该片段选中（时间线高亮） |
| 时间线选中一段文字片段 | 列表自动滚到并高亮那一条 |
| 播放 | 列表高亮"当前时间所在的字幕"（跟随滚动，但不抢用户手动滚动） |

**实现要点**：
- 播放头订阅用 `store.playheadBus`（高频通道），**不订阅 doc**（否则播放时每帧重渲染整个列表）
- 列表"当前项"用**派生字符串**（`useDoc` 返回字幕 id 而非对象），避免无限重渲染（EffectPanel 已有先例）

## 7. 待确认（5 项）

### ① 列表要不要显示"手动添加的文字"？

同源数据，技术上必然都在。问题是要不要**区分标注**：
- **A（推荐）**：都显示，手动文字加「文字」角标
- **B**：只显示"字幕"（需要额外区分标记，而数据里没有这个字段 → 要加字段，成本高）

### ② 时间轴视图的形态

- **A（推荐）**：横向条块（迷你时间线，能看节奏与空隙）
- **B**：纵向列表 + 每条显示一个时间刻条
- **C**：不做独立视图，只是"点击跳到时间线"

### ③ OpenCut 的 word-level 高亮要不要做？

OpenCut（floomhq 版）有逐词高亮，但**需要词级时间戳**：
- SRT 只有整条时间，没有词级
- 宿主 `transcribe()` 返回的 `TranscriptSegment` 是否带词级？**当前协议没有**
- 做的话要改 `AIModelPort.transcribe` 的返回类型（改契约，影响宿主）

**建议：不做**（成本高、收益偏窄，且要改宿主协议）。

### ④ 顶栏的 SRT 入口保留还是移走？

- **A（推荐）**：两处都留（顶栏是"文件级操作"、面板内是"顺手操作"），**同一份实现**
- **B**：只留面板（顶栏简化）

### ⑤ "批量平移"是否需要？

字幕整体对齐音频是真实需求（转写有时整体偏移），但也可以不做。
- **A**：做（选中多条 → 整体前移/后移 N 帧）
- **B**：不做（用户可以用时间线的多选拖动）

## 8. 验收标准

| 项 | 标准 |
|---|---|
| 零回归 | `npm test` 662 条全绿；`t11`（左栏）/ `t14` / `m3-export` 全绿 |
| 列表准确 | 条数 = 文字片段数；按起点排序；时间码精确到毫秒 |
| 联动 | 点一条 → 播放头跳 + 时间线选中（反向也生效）|
| 内联编辑 | 双击改文本 → 一个撤销步；`Esc` 不改数据 |
| 导入导出 | 导入 N 条 → 列表 N 条；导出内容能被自己的 `parseSrt` 读回 |
| 转写入口 | 无宿主通道时**禁用 + 说明**（不是点了没反应）|
| 全中文 | 所有标签中文（字幕 / 列表 / 时间轴 / 自动字幕 / 导入 / 导出 / 合并 / 平移）|
| 性能 | 500 条字幕时列表不卡（虚拟滚动或分页）|

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 长字幕（500+ 条）渲染卡顿 | 列表虚拟化（只渲染可视区）或用 `content-visibility: auto` |
| 播放时列表每帧重渲染 | 只订阅 `playheadBus` 算"当前条"，不订阅 doc |
| 字幕与文字混淆 | 列表加来源角标（待确认 ①）|
| 编辑文本时与 doc 更新打架 | 内联编辑用本地 draft，提交才 dispatch（同 `AdjustRow` 的教训）|
| 时间码编辑产生非法区间 | `core/captions.ts` 里统一 clamp + 重叠提示（单一判断点）|
