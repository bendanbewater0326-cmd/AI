## 用户实测两个 bug（音量 / 布局）—— 查出是同一个根因

用户报：① 素材在 V1 只有画面没声音；② 音量调到 5% 还是过响。

### 根因（同一个）
`InspectorPanel` 音量滑块 `onChange` 只写本地 state，**`onPointerUp` 才写 doc**。
pointerup 落在别处（点轨道跳值 / 键盘 / 触摸在别处抬起）→ 界面 5%、doc 还是 1。
若某次拖到 0 而 pointerup 落在别处 → doc 里留 gain=0 → "这条轨没声音"（V2 没调过所以正常）。

### 修法
- `onChange` 立即提交；`store.dispatch` 新增 `options.mergeKey`（窗口 1s，
  保留最早 inverses、ops 保留最早 from）→ 一次拖动 = 一个撤销步
- `setMasterVolume` 改直接赋值（`setTargetAtTime` 在 suspended 的 ctx 上不推进，
  "播放前调小"完全无效，实测 masterGain 一直是 1）；引擎重建后用 `volumeRef` 补一次
- 时间线给静音/只出画的片段画红色徽标（**画在左端**：右端在长片段上会跑出视口；
  **最后画**：否则被选中手柄盖住）
- 布局：时间线画布放进 `.v-tl-scroll`（overflow-y auto + scrollbar-gutter stable），
  轨道头按钮挂到 `.v-tl-inner` 跟着滚 —— 原来区域固定 220px、4 轨要 248px，
  1280×720 下 A1 整条在视口外（这就是"拖不到下面的轨"）
- compositor.endFrame 零图层时再清一次屏（花屏保险）

### 花屏未能复现
6 种素材（720p/1080p/HEVC/4K/竖屏/10 分钟）在"片段之前"都是纯黑。
已加保险 + 让 pcmProbe 暴露 masterGain；需要用户提供该文件或自检结果。

### 数字
479 单测 / 29 脚本；E2E 48；构建 585.7KB。

## 音量改成 dB 映射 + 峰值保护（用户给了完整规格）

### 旧实现的问题
`gain = 滑块值`（线性振幅 0..2）：100%→0dB，**50% 只有 -6dB**，200% 只到 +6dB。
下半程承担 -∞~-6dB、上半程只 6dB → "前半段没变化、后半段踩空"。

### 新映射（`src/core/volume.ts`，16 单测）
- 0<p≤1：dB = -60 + 60p（每 1% 走 0.6dB）
- 1<p≤2：dB = 12(p-1)（每 1% 走 0.12dB）
- p=0：真静音（gain 0）
- **存储仍是线性振幅**：老工程 gain=0.5 声音不变，只是滑块显示 90%
- `projectInput` 把 gain 上限夹到 3.98（+12dB）

### 峰值保护
`softLimit`：|x|≤0.9 恒等，之后 tanh 渐近到 **0.999**（给 16bit 留余量）。
- 预览 `applyClipGain`（只在可能超 0dB 时逐样本走）
- 导出 `mixTimelineAudio` 对最终混音再限一次（先扫峰值，没超不动）

### UI
属性栏 + 预览音量都显示 dB 为主、% 为辅；0% 时时间线有红色「静音」标记。

### 数字
495 单测 / 30 脚本；E2E 48；构建 587.1KB；72 文件 0 违规。

## 预览花屏 + 轨道状态不实时（两个核心 bug，四个独立缺陷叠加）

### ① 花屏根因：`preserveDrawingBuffer: false` + 按需重绘
浏览器合成过一次后就不再保证绘制缓冲有效。暂停时不重绘 → 任何重新合成
（缩放窗口/切主题/切标签页回来）都显示**未定义内存** = 黑白噪点/横条纹。
修：`preserveDrawingBuffer: true`（不是为截图，是为"暂停时画面稳定"）。

### ② 清屏被 `clear` 参数控制
"有没有内容"和"要不要清"是两件事。两条渲染路径（WebGL/2D）改**无条件整张清**；
`endFrame` 补"层数组非空但每层都被跳过"的分支（判据：本次跳过数 == 层数）。

### ③ 空内容没有成功语义 → 重试预算被耗死
`exact` 在 element 模式对空帧恒 false → 重试 5 次 → 预算满 → **之后所有重绘直接返回**。
修：`FrameResult.empty`（引擎 visible=0 时显式 beginFrame+endFrame 后返回）；
`renderPreviewFrame` 认 empty 为成功；`decoded=false` 也不算失败；新增 `repaintPreview()`。

### ④ 无效帧没拦截 → missing 不计数 → exact 假阳性
引擎侧加 `isDrawableSource()`，尺寸 0 按 missing 处理并 close 该帧。

### ⑤ 音频实时：轨道闸门（GainNode）
PCM 提前 1–3s 排期，改 doc 对已排期块无效。加 `trackGates: Map<trackId, GainNode>`，
`source → 片段增益 → 轨道闸门 → master`。`applyTrackGates()` 直接赋值 `gain.value`。
**不用 setTargetAtTime**：`AudioParam.value` 在自动化期间读不到实时值（一直 1），
导致"静音有没有到链路"测不出来——这类 bug 会反复回归。

### ⑥ 统一入口：store.subscribe + 轨道状态指纹
变了 → `applyTrackGates()` + `repaintPreview()`。按钮/菜单/Agent 都走 setTrackFlag/dispatch。

### ⑦ 顺手收敛两处 solo 遗漏
`collectAudibleClips`、`clipsNeedingExtraDraw` 还在用 `muted || hidden` → 改走
`isTrackAudible` / `isTrackVisible`。

### ⑧ 时间线隐藏轨压暗的两个坑
1. 必须画在轨道头列 `rulerBg` **之后**（先画会被整块盖住，实测 245→245）
2. 必须用**黑色蒙层**（换 trackAlt 只差 2–3 色阶，肉眼看不出）

### 测试

那个读 FBO，FBO 一直是干净的，测不出花屏）。

## S3 落地：轨道高度拖拽 / 复制 / 上移下移 / 拖拽排序

### 两个新 op（其余是组合）
- `setTrackHeight {trackId, from, to}` —— apply 里夹 24–120（文档永远合法）
- `reorderTracks {changes: [{trackId, from, to}]}` —— **批量**改 order，

复制轨道不是新 op = `reorderTracks` + `addTrack` + N×`addClip`，一次 dispatch 一个撤销步。

### `core/trackOps.ts`（新）
`buildDuplicateTrackOps` / `buildShiftTrackOps` / `buildMoveTrackOps` /
`trackDropTarget` / `heightFromDrag` / `clampTrackHeight`

### 排序不跨类型
视频/音频/字幕互不跨越（否则层级乱且用户看不出原因）。到边界时菜单项置灰 + 文案带原因。

### 高度拖拽
- 热区 5px（规范 3px 实测压不住），`bottom: -2px` 压在行分隔线上，hover 变主色
- `pointermove` 监听在 **window**（移出热区后元素收不到 move）
- 每次 move 都 dispatch + `mergeKey: track-height:<id>`

### 拖拽排序
- **4px 阈值**：否则双击改名的第一下就把轨道拖起来
- 拖动中只画 `ephemeral.trackDrag` 指示线，松手才 dispatch
- 指示线贯穿整条画布（含轨道头列）

1. `from` 取在 `drag.current = next` 之后 → 第一步是 next→next 无效 op，

3. 测试里给 `top` 又乘 DPR → 落到标尺区，targetIndex 恒 0。

## 素材持久化与重链（刷新必离线 + 重新链接无效）

### 四个独立缺陷（两个互相掩盖）
1. **重链按钮什么都不发生**：`await requestPermission` 之后才 `input.click()`，
   已脱离用户手势 → 浏览器拦掉文件框（内嵌面板 100%）。
   修：点按钮**第一件事**就弹选择器；"恢复授权"拆成独立按钮。
2. **重链成功后刷新又离线**：旧重链走 `importAssetFile`，固定写 `memory` + `handleRef:null`。
   修：统一到 `relinkAssetFromFile`（探测→写回同一 id→清缓存→写缩略图/handle→立刻重绘）。
3. **刷新后必然离线**：`restoreSession` 只标 `status=ok`，但 `previewSource` 是内存态、空的。
   修：`restoreSession` 返回 `restorableFiles`（granted 的 `handle.getFile()`），
   App 逐个 `probeMediaFile(file, null, assetId)` 重新注册（不 await，避免白屏）。
   `getFile()` 失败 → 降级 offline（"权限在、文件没了"是最常见场景）。
4. **注销无效**：`unregisterAsset` 用 `pool.release`（只关会话、留源）→ 下次取帧又能解。
   修：先同步 `pool.invalidate`（删源+清缓存），再异步关会话。

### 新模块
- `media/relink.ts`：`relinkAssetFromFile` / `relinkFromFiles` / `scoreCandidate` / `trackDropTarget`式纯函数
- `media/fileHash.ts`：前 1MB SHA-256，无 subtle 时 FNV-1a（带算法前缀，跨算法不可比）
- App：`OfflineBanner`（顶部琥珀色，3 个按钮）、`PreviewOfflineHint`

### 打分
指纹一致 100 / 名字+大小+时长全对 100（AUTO_LINK_SCORE=95）/ 只有名字 40 / 名字不同但大小+时长 60。
名字只给 40：用户重命名是主要场景之一。

### 视觉标识四处

### 三个坑
1. `engine.unregisterAsset` 内部 `void pool.unregister`（异步）与紧跟的同步 `register` 打架，
   把刚注册的源删了 → "重链成功但永远黑"。最终：池的 `register` 自己清旧会话+缓存（覆盖语义）。
2. `pool.release` 不删源 → 注销无效。
3. 时间线角标像素判据不能用"偏红像素数"（区域里本来有画面红：离线 187 / 恢复后 144），
   必须相对差值。

### 追加：`void asyncFn()` 的穿插陷阱（这轮最贵的一课）
给 `pool.register` 加"覆盖注册先 `void release()`"后，**MP4 导出没有音轨**、**粗剪找不到停顿**
（WAV 正常、预览正常，所以一开始完全看不出关联）。
根因：`release` 是 async，即使把 `cache.removeAsset` 提到同步段，
它启动的 promise 仍会穿插进调用方后续的 await —— 把导出混音刚缓存的音频样本清空。
修：用**纯同步的 `invalidate`**（同步摘会话引用 + 异步只关资源），
注册路径上不启动任何带副作用的 promise。

## 自动恢复优先（刷新后用户零操作）

### 四层
0. **宿主路径**（Electron）：`window.veditorHost.readFileByPath(path)` → 直读，不查权限
1. **句柄 granted**：`getFile` 直接重建（`restoreSession` 改成 `Promise.all` 并行，原来串行 1.5–3s）
2. **静默扫描**：扫描"用户授权过的目录"（批量重链时把目录句柄存进 IDB 新 store `directories`，DB v3）
3. **手动兜底**：全失败才显示离线条

### 关键限制（必须说清）
浏览器拿不到"文件的父目录"，所以第 2 层**只在用户显式授权过目录时可用**。
没有授权 → `scanned=0`，不假装扫过。

`showOpenFilePicker` 的句柄只在本次会话有效；刷新后 queryPermission 变 prompt。

（否则会闪一下"1 个素材离线"再消失，比不提示更不安）。

### 扫描约束
只收音视频扩展名 / 递归 1 层 / 上限 400 个候选 / 单文件失败不中断 / 候选**带句柄**

## 本地草稿素材缓存池（终极兜底）

### 核心
把字节复制进软件自己的存储，恢复不再依赖源文件是否还在原地。
恢复优先级：**缓存池 → 宿主路径 → 句柄 → 目录扫描 → 离线**。

### 两个后端
- Electron：`veditorHost.copyAssetToCache / readCacheFile / listCache / clearCache`
- 浏览器：**OPFS**（`navigator.storage.getDirectory()`）—— 选它而不是 IndexedDB，
  因为 `createWritable()` 是流式写，2GB 不会打满内存；IDB 存 2GB Blob 会让标签页崩。

### 命名即去重
`cacheFileName(hash, name)` = `sha256-xxx.mp4`（冒号换短横，Windows 文件名安全）。
同指纹三次导入 → 同一文件 → 天然去重。

### 无阻塞
导入完成后才入队（并发 2）。完成后 `store.updateAsset({cacheKey})`，
**不动句柄**（缓存只是多一条保命路径）。失败不报错。

### relink 的 handle 三态（关键）
- `undefined`：不改原句柄（缓存恢复用）
- `null`：显式清句柄（`<input>` 选文件）
- 句柄：写入并落 IDB

`cacheKey` / `contentHash` 必须从旧 asset 继承（不在 probeMediaFile 结果里）。

### 面板
顶栏「缓存」：后端类型 / 文件数 / 占用、自动缓存开关、清理未使用、清空全部（二次确认）。

### 四个坑
1. `assets()` 钩子字段裁剪 → 加了 cacheKey 但测试读不到（不是没写）
2. `evaluate` 字符串里不能有顶层 `await` → 报 `missing ) after argument list`
3. `localStorage` 不可写时开关失效 → 加内存兜底 `autoCacheMemo`
4. 性能断言又被负载骗（空闲 0.1ms / 满载 14ms）→ 阈值 25ms，只防数量级

### 数字
576 单测 / 35 脚本；E2E 52；构建 628.2KB；82 文件 0 违规。
新测试：`draft-cache.test.mjs`(11)、`verify-draft-cache.mjs`(12)。

## S5 摸底（`docs/s5-audit.md`）：13 项探针实测 + 修掉一个真 bug

### 修掉的 bug
`timelineController.pointerMove` 用 `floor((y - 24) / 56)` 算目标轨道 —— 56 是 S1 前的统一行高。
S3 后是 60/50/32 且可拖到 120 → 改高后跨轨落到错误的轨；
更坏：行号越界时 fallback 回原轨 → "拖了完全没反应"，极难归因。
改用 `trackRowAtY(trackLayout(doc), y)`。实测 V3→V2 修复后正确。
顺带删了 `TIMELINE_TRACK_HEIGHT = 56` 等三个 S1 遗留死常量。

### 已具备（实测）
水平拖动 / 首尾裁剪（手柄不要求先选中）/ 磁吸（0+播放头+片段边界，8px，有吸附线）/

拖入素材 / 锁定拦截 / 拖出左边界 clamp 到 0

### 缺口
- **多选全是"数据层有、界面没接"**：`store.toggleSelection`/`getSelection` 完整实现，

- 反馈类完全没做：时长气泡、跨轨指示线、Shift 波纹裁剪
- 半实现：裁剪不吸附（snapFrame 只在 move 分支）、磁吸缺"整数秒"目标

鼠标事件落到工具栏上）。→ "拖拽边缘自动滚动"不是锦上添花。

### 测试坑（这次踩的）
- 探针坐标不要 `/(canvas.width/rect.width)`：rect 与 layout 都是 CSS 像素，除完 y 缩一半落到预览区

## S5 P0 落地：裁剪吸附 / Ctrl 加选 / 多选删除 / 拖出界提示

## UI 重构 S1.2 落地（三栏百分比 + 拖拽 + 折叠）

### 布局
```
--v-topbar-h: 48px   --v-left-w: 25%   --v-splitter-w: 4px   --v-right-w: 25%
.v-body { grid-template-columns: var(--v-left-w) var(--v-splitter-w) minmax(0,1fr) var(--v-splitter-w) var(--v-right-w) }
```
中间必须 `minmax(0,1fr)`：`1fr` 的最小尺寸是 `auto`，预览画布固有宽度会撑破中间列。

### 关键实现
- `ui/splitter.tsx`：`PANEL_MIN_PCT=15 / MAX=40 / DEFAULT=25`；
  `applyPanelWidth` 写根节点 CSS 变量；`currentPanelPct` 读回；
  `readStoredPct / readStoredCollapsed / storePct / storeCollapsed / hasStoredPct`
- 拖拽**不 setState**：`pointermove` 直接改 CSS 变量，松手才写 localStorage。
  监听挂 `window`（4px 细线，指针一离开元素就收不到 move）
- 折叠 = 面板 `display:none` + 列宽 `0px`。不用 `width:0`（padding 会撑住，实测剩 21px；
  且宽度 0 元素还在 → Tab 能聚焦到看不见的按钮）
- 折叠按钮贴 `top: 8px` 且折叠态常显（面板 0 宽后唯一能点的东西）

### 三个真实 bug（E2E 抓出来的，肉眼看不出来）
1. **折叠按钮盖住分隔条**：4px 条上放 12px 按钮并居中 → 整条都是按钮，拖拽完全没反应。
   修：按钮移到顶部，中间 100% 高度留给拖拽。
2. **折叠左栏后预览宽度变 4px**：`display:none` 让面板脱离 grid 流，剩下 4 项**自动放置
   往前挤一格** —— 左分隔条占第 1 列（25%）、预览落到第 2 列（4px 分隔条列）、右栏落到第 4 列。
   修：5 个子项全部写死 `grid-column: 1..5`。
   **阴点**：折叠右栏时断言是通过的（尾部少一项，前面列号不变），只有折叠左栏才暴露。
   → 布局必须两个方向都测。
3. **窄屏媒体查询是死代码**：挂载时无条件 `applyPanelWidth` 写行内 `--v-left-w: 25%`，
   行内优先级高于 `:root` 媒体查询 → 820px 窗口下左栏仍 205px，缩略图挤成一列。
   修：新增 `hasStoredPct()`，**只在拖过时**才写行内值。

### 测试教训（最重要的一条）
⑫ 一开始写"清 localStorage + 手动 `removeProperty` 掉行内值 → 断言 16%"，
等于替出问题的挂载代码擦屁股，**带 bug 也是绿的**。
改成"清 localStorage → 缩到 820px → 真的 `location.reload()`"后，
带 bug 读到 25.2%、修好 16.1%，断言才算有牙。
**通用原则：测"挂载/初始化"逻辑时，必须让那段代码真的跑一遍，别在测试里手动补齐它的副作用。**

### 一处刻意偏离
媒体查询不用 `clamp()`：`clamp` 返回长度，写进 `grid-template-columns` 会和拖拽的
百分比打架（拖到 40% 被悄悄改回 16%）。用 ≤1024px → 20%、≤820px → 16% 覆盖变量。
