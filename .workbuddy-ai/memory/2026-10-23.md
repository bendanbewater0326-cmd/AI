## S1.4 落地：时间线高度 50%（15%–70% 可拖）

用户要求：默认 50%、可拖 15%–70%、复用分隔条组件（热区与左右栏一致）、
localStorage 记住高度、**只动布局层**（渲染/素材/业务逻辑零改动）。

### 关键决定：百分比只存在"无单位变量"里

```css
--v-timeline-pct: 50;                                                   /* 唯一真相 */
--v-timeline-h: calc((100vh - var(--v-topbar-h)) * var(--v-timeline-pct) / 100);
```

`--v-timeline-h` 有三类消费者：grid 行高、预览 16:9 的宽度计算、命令栏/toast 的 `bottom`。
后两者要求它是**长度**。若把它直接定义成 `50%`，`calc(100vh - … - 50%)` 里的 50% 会按
**宽度**解析（属性语境决定百分比基准）→ 预览尺寸静默算错，不报错、只是"看起来小一点"。

### splitter 抽成三面板共用

`PANELS` 表描述每个面板：轴（x/y）、变量名、单位（`%` / 空）、存储键、方向 sign、min/max。
时间线：y 轴、`sign = -1`（往上拖变大）、范围 15–70、**无折叠按钮**
（高度归零后没有任何替代入口）。热区仍 4px；拖拽时 body 加 `v-splitter-dragging--y`
→ `row-resize`。

### 顺手删的死代码

`TimelineView` 里 `.v-timeline__splitter` 是个 `aria-hidden` 的空 div，**从未接过事件**
（`ui-refactor-plan` 里写的"已经能拖"是假设，实际没有）。改成 `.v-workspace` 第 2 行的
真分隔条，三行全部显式 `grid-row`（S1.2 的同一课：别依赖自动放置）。
`.v-stage__screen` 的宽度 calc、`.v-cmdbar` / `.v-toast` 的 `bottom` 都补了 `--v-splitter-h`。

### 两个坑

1. **`calc()` 之后不能拿 `getPropertyValue` 做数值断言**：`uiLayout().vars.timelineH`
   读出来是 `calc((100vh - 48px) * 50 / 100)` 这串 token，不是 `380px`。
   测试一律读元素 rect（`uiLayout().timeline.h`）。
2. 15% 时时间线只有 109px（工具栏 28 + 标尺 24 = 52，剩 57 < 一条 60px 视频轨），
   轨道区靠 `.v-tl-scroll` 滚动 —— 预期行为，不是裁切。

## S1.5 落地：控制栏叠到画面底部居中（UI 重构线收官）

用户要求：绝对定位叠在**预览画面**底部居中、半透明黑 + 圆角、不占垂直空间；
鼠标移入保持清晰、移出降低透明度；控件与快捷键零改动。

### 实现
- `.v-stage` 从 `minmax(0,1fr) var(--v-ctrlbar-h)` 改成**单行**；
  控制栏 DOM 移进 `.v-stage__screen`（16:9 画面盒），`absolute; bottom:12px; left:50%`。
  **必须挂在画面盒而不是舞台**：挂舞台时画面留黑边，控制条会漂到黑边上。
- 视觉：`rgba(0,0,0,.55)` + `backdrop-filter: blur(6px)` + 8px 圆角 + 0.5px 浅白描边，**无阴影**。
  默认 `opacity:.55`；`:hover`（画面/条）+ `:focus-within` → 1。
- `.v-stage__screen` 补 `position: relative` —— 顺带修掉「素材已离线」提示的隐性错位
  （它 `bottom:12%` 一直按 `.v-workspace` 在算）。
- 预览宽度 calc 去掉 `--v-ctrlbar-h` → 1440×900 下画面 595×335 → **626×352**。

### 补了两个控件（原清单有、代码里没有）
控制栏原本只有「播放 / 时间码 / 音量」，**没有上一帧/下一帧**。
补 `frame-prev` / `frame-next`，直接复用 `onSeek`（`transport.seekTo`），零新增逻辑；
图标用内联 SVG，不用 ⏮/⏭（Windows 走彩色 emoji 字体，跟 ▶ 对不齐）。

### 两个测试教训（写进 PROJECT-STATUS §9.3）
1. **有音轨素材在无头里播放头不动**：`play()` 优先选音频时钟，AudioContext 在无头里不推进
   → `derivedFrame()` 永远算回 anchor 帧。表现：`aria-pressed=true` 但 frame 2 → 2。
   换 `silent-720p.mp4` 立刻 2 → 62。**测"播放真的推进"必须用无音轨素材。**
2. **`element.click()` 绕过命中测试**：控制栏叠在 canvas 上，必须用
   `Input.dispatchMouseEvent` 真实点击 + `elementFromPoint` 命中自身，否则"点不到"测不出来。

### 全量回归的一次偶发
`verify-s5-p0` 在 run44 里红了（`⑥ 拖出轨道区：位置 0 → 24`），单独跑必过。
根因是它 `drag()` 的最后一次 mousemove 与 mouseReleased 之间**零间隔**，
负载高时最后那次移动被丢掉 → pointerup 用了上一格（还在轨道里）的位置。
修法：松手前**复述一次落点 + 60ms 间隔**。连跑 3 次全过。

## 左栏文本面板方案（`docs/text-panel-plan.md`，待用户确认）

用户下一批要做左栏 **文本 / 转场 / 特效** 三个面板，先从文本开始，要求先出方案。

### 核对出的关键事实
- `TextContent` 只有 7 个字段：content / fontSize / color / align / x / y / background。
  `background` 是**底衬**（按最长行测宽 + 圆角），支持多行（`\n`），行高固定 1.28。
- `x/y` 是**绝对像素**（相对画面中心），4K 工程下同值会显得偏小 —— 已知限制。
- 预设系统（R-053）**已经支持文字样式**（`payload.textStyle` 只存样式不存内容），
  "我的预设"可以直接复用，不用新建存储。
- **文字从来没有落在文字轨上**：`addText()` 和 `buildSubtitleReplaceOps`（SRT/转写）
  都是"找最上层视频轨"。`TrackKind 'text'` + `nextTrackFor` + `collectVisibleClips`
  里的"字幕轨也要参与合成"全都现成，只是没被用起来。
  → 选"改落文字轨"就必须**同批改 SRT/转写**，否则两套规则。

### 方案要点
- 纯 UI 能撑起 10 个视觉差异明显的预设（字号/颜色/底衬/对齐/XY）；
  **花字做不出来**（没有 bold / stroke）→ 作为 A 选项请用户拍板（建议加两个可选字段，约 40 行）。
- 缩略图用 DOM 画（不用 canvas）：字号按 `cardW/1080` 等比缩放，可被 E2E 用 DOM 断言。
- 点击三态：选中文字片段→套样式保留内容；选中别的/没选→新建 3 秒片段。
- 三步交付：①数据+面板+点击 ②拖拽+落轨（含 SRT）③我的预设。

### 待确认（4 项）
A 加不加 bold/stroke；B 改不改文字轨；C 预设清单；D 是否同意分三步。

## 文本面板第 1 步交付（模板库 + 点击应用）

用户确认 A=加 bold/stroke、B=改落文字轨（同批改 SRT/转写）、C=3 秒、10 个模板清单照做。

### 落地
- `core/textPresets.ts`：10 个模板（标题 4 / 字幕 3 / 标注 2 / 金句 1）+ 5 个分类 +
  `presetToText(preset, content?, size?)`。
- `ui/TextPanel.tsx`：分类 chips + `auto-fill minmax(120px,1fr)` 网格 + 底部「＋ 添加文字」；
  缩略图**用 DOM 画**（`container-type: size` + `cqw/cqh`），字号放大 1.8 倍 + 6px 下限，
  否则 136px 卡片里 88px 标题只有 6px 高、完全看不清。
- `TextContent.bold?/stroke?`：**4 处归一化**（types / textLayer 的 key+绘制 / preset 抓取与
  normalizePayload / projectInput.normalizeText），漏一处就是"存盘丢样式"。
- `core/placement.ensureTextTrackOps`：有 T 轨复用、没有就建；建轨 + 落片**同批 dispatch**。
- 属性栏补「加粗」「描边」+ 描边粗细（不然套了「金句描边」就去不掉）。

### 最大的坑：模板坐标是绝对像素
`TextContent.x/y/fontSize` 都是项目绝对像素。模板按 1080p 写，`?src=` 素材是 **1280×720** →
半画面只有 360px，`y=380` 的「底部字幕」被**推出画面**，预览纯黑，而 doc 字段全对。
像素断言第一次是 `0.00 → 0.00`（全黑）才暴露的。
修法：`presetToText` 按 `height/1080` 缩放字号/描边/y、按 `width/1920` 缩放 x。
副作用：4K 偏移偏小的问题一并解决（原方案把它列为"已知限制"）。
