## S1.4 落地：时间线高度 50%（15%–70% 可拖）

用户要求：默认 50%、可拖 15%–70%、复用分隔条组件（热区与左右栏一致）、
localStorage 记住高度、**只动布局层**（渲染/素材/业务逻辑零改动）。

### 关键决定：百分比只存在"无单位变量"里

```css
--v-timeline-pct: 50;                                                   /* 唯一真相 */
--v-timeline-h: calc((100vh - var(--v-topbar-h)) * var(--v-timeline-pct) / 100);
```

`--v-timeline-h` 有三类消费者：grid 行高、预览 16:9 的宽度计算、命令栏/toast 的 `bottom`。
后两者要求它是**长度**。若把它直接定义成 `50%`，`calc(100vh - … - 50%)` 里的 50% 会按
**宽度**解析（属性语境决定百分比基准）→ 预览尺寸静默算错，不报错、只是"看起来小一点"。

### splitter 抽成三面板共用

`PANELS` 表描述每个面板：轴（x/y）、变量名、单位（`%` / 空）、存储键、方向 sign、min/max。
时间线：y 轴、`sign = -1`（往上拖变大）、范围 15–70、**无折叠按钮**
（高度归零后没有任何替代入口）。热区仍 4px；拖拽时 body 加 `v-splitter-dragging--y`
→ `row-resize`。

### 顺手删的死代码

`TimelineView` 里 `.v-timeline__splitter` 是个 `aria-hidden` 的空 div，**从未接过事件**
（`ui-refactor-plan` 里写的"已经能拖"是假设，实际没有）。改成 `.v-workspace` 第 2 行的
真分隔条，三行全部显式 `grid-row`（S1.2 的同一课：别依赖自动放置）。
`.v-stage__screen` 的宽度 calc、`.v-cmdbar` / `.v-toast` 的 `bottom` 都补了 `--v-splitter-h`。

### 两个坑

1. **`calc()` 之后不能拿 `getPropertyValue` 做数值断言**：`uiLayout().vars.timelineH`
   读出来是 `calc((100vh - 48px) * 50 / 100)` 这串 token，不是 `380px`。
   测试一律读元素 rect（`uiLayout().timeline.h`）。
2. 15% 时时间线只有 109px（工具栏 28 + 标尺 24 = 52，剩 57 < 一条 60px 视频轨），
   轨道区靠 `.v-tl-scroll` 滚动 —— 预期行为，不是裁切。
