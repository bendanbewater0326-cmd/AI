## 踩坑

1. **esbuild `base64` loader ≠ data URL**：它导出裸 base64 字符串；带 `data:...;base64,` 前缀的
   是 **`dataurl` loader**。三处（build/dev/测试 harness）都要写 `dataurl`。
2. **`Uint8Array<ArrayBufferLike>` 进不了 `Blob`/`File`**（TS 5.9）：按 `zip.ts` 先例标
   `Uint8Array<ArrayBuffer>`。
3. 脚本要放 `.mjs`（package.json `"type":"module"`，`.cjs` 里写 import 会炸）。
4. `npm test` 是**显式清单不是 glob**——新测试文件必须手动补进 package.json（settings 当年漏过）。
5. ffmpeg `aeval` 是处理滤镜不是源；合成源要用 `aevalsrc=...:s=48000:d=...:c=mono`。
6. **ffmpeg `sine` 源默认振幅只有 1/8（实测峰值 -18dB）**——合成正弦必须补增益。
   第一版音效栽在这：whoosh 峰值 -41dB、beep -20dB，用户试听"没有任何声音"；
   "0 秒"则是资源管理器把不足 1 秒的时长显示成 0:00（文件本身有效）。
   修复：逐个补增益 + 生成后 volumedetect **响度门禁**（max_volume ∈ [-16,-1]dB，
   超出直接失败）+ beep 0.15→0.3s + 新增 `_preview.m4a` 一键试听串烧。
7. **AAC 是专有编解码器，"系统播放器能播"≠"Chromium webview 能播"**（同日第二轮反馈）：
   用户在 ZCode 客户端点开 m4a 预览无声，但 Windows 自带媒体工具正常——ZCode 的文件
   预览是开源 Chromium 系 webview，默认不带 AAC 解码 → 静默无声。**不是产物问题**：
   应用目标环境 Edge/Chrome/WebView2 都带 AAC 解码（`tests/cdp.mjs:19` E2E 用 Edge，
   全量 E2E 用 AAC 素材长期验证）。处置：`gen-sfx.mjs` 追加生成
   `src/ui/audio/sfx/_preview.wav`（WAV=PCM 任何内核都认，**已 gitignore** 不进仓库）；
   `audio-panel-plan.md` §7.0 记入风险——未来宿主若是精简 Chromium 内核，上线前要在
   SelfCheck 补 AAC 解码能力自检。
8. **ZCode 客户端连 WAV 也不响 → 其文件预览面板根本不出音频**（不是解码问题，PCM 都静音）。
   已用 `tests/probe-sfx-decode.mjs`（CDP 启 E2E 同款 Edge，`AudioContext.decodeAudioData`
   逐个解码测波形）拿到硬证据：10 个音效在应用目标内核里时长/峰值全部达标
   （peak 0.18–0.77）。**试听验收以系统播放器或该探针为准，客户端预览不可用。**
